# 下载任务的恢复、失败与完成语义

Type: grilling
Labels: wayfinder:grilling
Status: open
Blocked by: 01, 03, 05
Assignee: none

本议题确定下载行为、数据保护与镜像可用声明之间的边界，不将全部高级下载功能默认塞入第一版。

## Question

第一版需要怎样的任务状态与保障，才能在大文件、网络中断、重复选择、取消和应用重启后仍产生可信的镜像内容，并确保镜像索引只反映已完成且校验通过的下载？

基于 [nvm 双客户端与 Nexus 路径的兼容契约](01-mirror-protocol.md)、[Tauri 跨平台下载与输出目录的技术约束](03-tauri-constraints.md) 和 [部分镜像的索引、校验文件与可用性承诺](05-partial-mirror-policy.md)，与用户确定必要范围：

- 进度、取消、失败重试、暂停和重启恢复中，哪些必须在第一版具备。
- 并发边界、批次与文件任务关系，以及新增批次/重复任务的行为。
- 已有同名文件、校验失败、磁盘空间不足与目录不可写时，哪些动作可自动做，哪些必须确认；不能静默覆盖已存在数据。
- 临时文件、下载完成、校验通过、最终文件与元数据的完成条件，以及校验的信任依据；文件大小正常或网络请求完成不自动等于镜像可用。
- 镜像可用内容记录和索引在什么条件下更新，如何面对文件提交成功但索引更新失败、索引生成中断、重复任务或重启后的状态不一致；未完成和校验失败内容不得纳入可用声明。
- 用户选择的输出根目录及其 `nodejs/` 内容如何与任务绑定；目录改变、被移动或暂不可用时，任务与记录如何处理。
- 追加下载、重新校验或文件被外部修改后，怎样恢复镜像内容与索引的一致性；需要用户介入的边界仍待确定，不默认删除既有文件。

加载 `grilling` 和 `domain-modeling`。决定业务状态与用户承诺，具体实现留给技术路线议题；本阶段不增加 Python、Go 任务或 Nexus 上传状态。
