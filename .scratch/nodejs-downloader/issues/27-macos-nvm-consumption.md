# 27: 验证 macOS 上 nvm-sh 的真实镜像消费

**What to build:** 通过真实客户端验证应用生成的部分镜像能够在 macOS x64/ARM64 上发现发行版本、精确安装和运行，并验证 xz/gzip 及共享索引的别名/缺文件限制。交付的是可复现消费证据，不新增下载器安装或配置 nvm 能力。

**Blocked by:** 22 — 安全追加、重新核验与恢复镜像索引一致性。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 固定 `nvm-sh v0.40.8`，在 macOS x64 与 ARM64 实际安装运行对应架构 Node.js；允许虚拟机，模拟协议或仅静态路径检查不能替代。
- [ ] 每个架构分别验证 `.tar.xz` 和 `.tar.gz`，通过客户端工具环境控制格式，不改客户端源码；请求日志与操作证据证明实际取得并使用对应归档。
- [ ] 选择官方清单证实具备必需文件的发行版本，由正式应用准备实际镜像；控制匿名 HTTPS 静态消费入口，不依赖目录 HTML、软链接或交互下载认证。
- [ ] 在独立或明确清理缓存的客户端环境，发现结果对应测试镜像子集，不包含未收录上游发行版本；记录缓存前提，不要求客户端立即刷新所有旧缓存。
- [ ] 精确版本安装请求的索引、清单和归档来自测试镜像，安装后实际执行 `node --version` 与所选发行版本一致，记录客户端系统/架构和工具环境。
- [ ] 验证客户端支持的 latest、LTS、主版本选择依据共享镜像子集解析；所选目标本机必需文件齐备时可安装，不把镜像最新或客户端 LTS 宣传为官方最新/当前受支持 LTS。
- [ ] 构造仅其他平台齐备的发行版本，记录其可被发现及别名可能选中本机不可安装目标的限制；不要求自动选择本机次新发行版本或应用自动补齐。
- [ ] 缺本机文件时记录实际解析、请求和失败/回退，不以回源、切换镜像或源码构建后的成功计为本镜像通过。
- [ ] 允许必要外围联网，但须证明不掩盖镜像缺失，不宣称完全离线；HTTP 内部测试不能代替最终匿名 HTTPS 验收。
- [ ] 汇总客户端固定版本、两个架构各两格式、测试发行版本/镜像子集、环境设置、操作、安装/运行结果及 HTTPS 请求日志；任一未执行或缺环境记待验证，失败记失败。
- [ ] 如发现导出内容违反契约，提供复现和错误结果，不以修改客户端或扩大镜像范围掩盖；本票不等待安装包，但消费结果不能替代原生桌面安装验收。
- [ ] 测试服务对外暴露内容、客户端环境安装/修改及删除内容按项目授权要求执行，不公开发布用户镜像；本地 ticket 授权不等于外部服务部署或红线操作授权。
