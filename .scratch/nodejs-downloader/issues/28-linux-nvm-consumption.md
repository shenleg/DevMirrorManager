# 28: 验证标准 Linux 上 nvm-sh 的真实镜像消费

**What to build:** 通过真实客户端验证应用生成的部分镜像能在标准非 musl Linux x64/ARM64 上发现、精确安装和运行，并覆盖 xz/gzip、别名及缺本机文件边界；不新增 Linux 桌面应用或 musl 支持。

**Blocked by:** 22 — 安全追加、重新核验与恢复镜像索引一致性。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 固定 `nvm-sh v0.40.8`，分别在标准非 musl Linux x64 与 ARM64 实际安装并运行对应架构 Node.js；固定并记录发行版、系统、架构和工具环境，不限定产品为某个 Linux 发行版。
- [ ] 每个架构分别真实消费 `.tar.xz` 与 `.tar.gz`，用客户端工具环境控制、不修改客户端源码；请求日志证明实际使用格式，不仅检查镜像中有两份归档。
- [ ] 选择真实官方必需文件齐备的发行版本，由正式应用生成镜像，在受控匿名 HTTPS 内容入口消费；不依赖目录 HTML、软链接、旧 discovery 元数据或交互认证。
- [ ] 允许虚拟机但必须运行目标架构 Node.js；仅协议模拟、跨架构文件存在性或 HTTP 内部测试不能替代最终链路。
- [ ] 独立或明确处理缓存的客户端发现测试镜像子集，不误含未收录发行版本；精确安装使用镜像的索引/清单/归档，`node --version` 与选择一致。
- [ ] 验证客户端支持的 latest、LTS、主版本按共享子集解析，本机必需文件齐备时安装成功；镜像最新不等于官方最新，客户端 LTS 不等于应用支持状态。
- [ ] 覆盖只有其他平台齐备的发行版本被发现和别名选中本机不可安装目标；记录预期限制，不要求自动次新回退或补齐未选目标。
- [ ] 缺本机文件时记录失败/实际回退，不能把回源、切换镜像或源码构建成功当作本镜像通过；必要外围联网不掩盖缺文件，不声称完全离线。
- [ ] 证据涵盖两个架构各两格式、固定客户端、系统/工具、镜像子集、测试发行版本、步骤、解析、安装/运行结果及 HTTPS 请求日志。
- [ ] 未执行、缺环境或失败逐项明确记录，不把其他架构通过代替缺失组合，不宣称全部历史发行版本或所有 Linux 发行版兼容。
- [ ] 如发现镜像契约缺陷，给出可复现差异，不通过添加 musl、修改客户端或扩大范围掩盖；本票不新增 Linux 安装包，不替代原生桌面验收。
- [ ] 测试环境、外部服务暴露及客户端安装按项目授权执行，不公开发布镜像，删除/凭证/部署等红线操作另外确认。
