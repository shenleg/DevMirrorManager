# 同一目标平台的分发变体支持范围

Type: grilling
Labels: wayfinder:grilling
Status: resolved
Blocked by: 01, 02
Assignee: collin

本议题决定第一版如何面对同一操作系统与 CPU 架构下并存、不可互换的分发变体，不擅自扩大用户确认的选择范围。

## Question

官方清单已经出现 `linux-x64` 与 `linux-x64-musl` 等同一目标平台的不同分发变体。第一版是只支持 nvm 常用的标准变体，还是允许用户明确选择其他变体？如何避免把它们静默合并或错当成不同压缩格式？

依据 [官方版本目录与当前受支持 LTS 的判定依据](02-release-catalog.md)，与用户决定：

- 第一版的变体白名单/识别边界，以及未识别文件如何呈现。
- 标准变体之外的文件是否具备本地镜像内容准备价值，是否可供目标 nvm 客户端实际安装；不能以官方可下载等同于 nvm 默认可消费。
- 若包含多个变体，批量选择、默认勾选与原始路径展示如何保持清晰；实际交互在 [搜索、多选与目标平台组合的交互模型](04-selection-interaction.md) 中设计。
- 文件清单加载失败时是否暂不可选择、何时重试；禁止从四维组合推导不存在的文件。

加载 `grilling` 与 `domain-modeling`。本议题解决支持边界，后续交互原型展示已确认边界，不实现下载功能。

## Answer

用户于 2026-10-13 确认第一版的分发变体边界如下：

### 支持范围

- 消费客户端保留 nvm-sh `v0.40.8` 与 nvm-windows `v2.0.1` 的既有契约，macOS 上的 nvm-sh、Windows 上的 nvm-windows 与 Linux 消费均在第一版范围内。客户端版本与格式依据见[部分镜像的索引、校验文件与可用性承诺](05-partial-mirror-policy.md)及[双客户端兼容调研](../research/mirror-protocol.md)。
- Linux 按通用 Linux 目标处理，不区分 Debian 等具体发行版；只采用官方标准 `linux-x64` / `linux-arm64` 分发文件。第一版统一排除所有 `*-musl` 变体，即使某发行版本的官方清单列出了这些文件也不纳入支持。
- 分发变体不是新增的用户选择维度。原有发行版本、操作系统、CPU 架构和文件格式选择保持不变；不提供 musl 变体开关，也不需要增加变体选择或诊断界面。

### 清单与可用内容

- 只依据对应发行版本的官方 `SHASUMS256.txt` 识别真实分发文件，不从操作系统、架构和格式组合推断文件存在。官方样本清单和文件差异见[版本目录调研](../research/release-catalog.md)。
- 非支持范围内的文件（包括 musl 变体及其他无法识别的分发候选）不供选择、不下载、不计入镜像可用内容，也不额外显示诊断列表。镜像可用内容仍须符合[部分镜像的索引、校验文件与可用性承诺](05-partial-mirror-policy.md)及[下载任务的恢复、失败与完成语义](06-download-lifecycle.md)。
- 某发行版本的清单加载或解析失败时，受影响的选择暂不可用，并提供明确错误与用户主动重试入口；其他清单已成功加载的发行版本不受影响。不得根据 OS、架构或格式推断文件存在。
- 保留上游文件名和相对路径。共享索引仍遵守既有部分镜像规则：版本被发现不代表每个目标平台都具备其所需文件，精确安装仍要求对应内容已下载并校验通过。

具体选择清单的交互布局由[搜索、多选与目标平台组合的交互模型](04-selection-interaction.md)继续决定；本议题不增加分发变体界面。

## Comments

- 2026-10-13：由官方清单中的真实变体差异毕业为独立决策议题；是否纳入第一版尚未获得用户确认。
- 2026-10-13 resolution：用户确定 Linux 采用标准 `linux-x64` / `linux-arm64` 构建并排除 musl；Linux 消费目标不限定 Debian 等具体发行版。原 Debian-only 边界由本次明确决定取代。
