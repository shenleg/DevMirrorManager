# 第一阶段：Node.js 桌面下载器与部分镜像准备规格

Labels: ready-for-agent
Status: ready-for-agent

本规格汇总已经确认的第一阶段产品、实现与验收决定，供后续开发执行；不表示正式应用已实现、安装包已构建或兼容验收已通过。

## Problem Statement

用户需要选择性准备 Node.js 官方分发内容，供 nvm-sh 和 nvm-windows 从同一个镜像入口发现发行版本并安装。手工下载容易遗漏客户端实际需要的压缩格式与校验文件；直接复制上游全量索引又会让客户端发现本地并不存在的内容。

用户还需要按版本号搜索、筛选当前受支持 LTS、选择目标系统与架构，并把文件保存到自己指定的目录。下载过程必须能解释进度、取消、失败和部分结果，保护已有文件，并避免把网络请求成功、文件齐备或历史成功记录误称为镜像可交付。

应用需在 macOS 和 Windows 上可直接安装运行，下载器运行平台不限制可下载的目标平台。本阶段只准备本地镜像，不安装 Node.js、不配置 nvm、不调用 Nexus 上传 API。

## Solution

提供 React/TypeScript 与 Tauri 2/Rust 实现的桌面下载器。用户从固定官方来源浏览发行版本，按文本前缀搜索及当前受支持 LTS 筛选，每次选择一个发行版本与一个目标平台，直接提交到共享、有界并发的下载队列。

应用按目标平台自动确定必需格式，保留原始官方校验清单与签名附件，将下载完成且 SHA-256 校验通过的分发文件保存到用户选择的输出根目录内的 `nodejs/`。多个下载请求复用同一镜像中的相同文件；取消一个下载项不停止其他下载项仍需的文件。

应用按实际重新核验后的镜像可用内容生成共享 `index.tab`。某发行版本至少有一个目标平台的必需文件齐备即可收录，但不得宣称其他目标平台可用。按镜像根目录展示文件、可用目标、索引协调及可交付状态；同根仍有未完成写入或索引未确认时，不宣称可交付。正常关窗与主动退出统一执行可解释的安全停止及收尾，重启后由用户手动恢复。

## User Stories

1. 作为镜像准备者，我希望在 macOS Apple Silicon、macOS Intel 或 Windows x64 上直接安装运行下载器，以便不必自行搭建开发环境。
2. 作为镜像准备者，我希望从 Node.js 官方来源取得上游版本目录，以便选择真实发行版本而不是依赖内置的过时列表。
3. 作为镜像准备者，我希望通过版本号文本前缀搜索，以便快速找到某个主版本或更具体的版本范围。
4. 作为镜像准备者，我希望搜索忽略首尾空白和可选前导 `v`，以便直接使用常见版本号写法。
5. 作为镜像准备者，我希望结果按语义版本降序排列，以便先看到较新的发行版本。
6. 作为镜像准备者，我希望只选择一个发行版本，以便清楚理解一次下载项的范围。
7. 作为镜像准备者，我希望筛选当前受支持 LTS，以便排除已停止维护的历史 LTS 和进入 LTS 前的发行版本。
8. 作为镜像准备者，我希望区分发行版本的 LTS 标记与发布线支持状态，以便不把历史标记误当成当前维护承诺。
9. 作为镜像准备者，我希望生命周期资料缺失或失效时看到未知状态及结果不完整提示，以便不被错误的支持判断误导。
10. 作为镜像准备者，我希望 UTC 日期变化及生命周期更新后重新判断支持状态，以便应用不在 EOL 后继续把发行版本标为当前受支持。
11. 作为镜像准备者，我希望手动刷新版本目录与生命周期数据，以便主动取得更新的信息。
12. 作为镜像准备者，我希望看到发布线最新发行版本及旧补丁提示，以便知道所选旧补丁可能没有后续安全更新。
13. 作为镜像准备者，我希望了解支持状态依赖本机时间，以便在系统时钟不准确时正确理解结果。
14. 作为镜像准备者，我希望搜索或筛选使当前发行版本失配时只清除发行版本选择，以便保留目标系统与架构且不被自动改选。
15. 作为镜像准备者，我希望未提交选择变化不影响已提交下载项，以便继续浏览其他发行版本。
16. 作为镜像准备者，我希望选择 macOS、Windows 或标准 Linux 的 x64/ARM64 目标，以便在任一受支持下载器运行平台准备约定目标的文件。
17. 作为镜像准备者，我希望始终能浏览范围内的系统与架构选项，以便查看不同组合的真实文件情况。
18. 作为镜像准备者，我希望标准 Linux 文件与 musl 变体不混用，以便不会得到不适合约定客户端环境的文件。
19. 作为镜像准备者，我希望应用自动确定客户端需要的格式，以便不必理解不同 nvm 环境的格式选择差异。
20. 作为镜像准备者，我希望 macOS/Linux 同时准备 `.tar.xz` 和 `.tar.gz`，以便覆盖 nvm-sh 的两种消费环境。
21. 作为镜像准备者，我希望 Windows 准备 `.7z`，以便满足约定 nvm-windows 的标准在线安装请求。
22. 作为镜像准备者，我希望成功取得清单后才判断文件缺失，以便不把网络或解析失败误认为目标不支持。
23. 作为镜像准备者，我希望清单获取失败时看到错误及主动重试入口，以便处理问题后重新选择下载。
24. 作为镜像准备者，我希望提交前看到发行版本、目标平台、必需输出文件与目录，以便理解将要准备的内容。
25. 作为镜像准备者，我希望通过原生目录选择器指定输出根目录，以便把镜像保存到仓库之外的合适位置。
26. 作为镜像准备者，我希望尚未指定目录时点击下载先选择目录，取消则不提交，以便不会意外产生任务。
27. 作为镜像准备者，我希望有效选择点击下载直接入队，以便连续提交不同组合而不反复确认下载。
28. 作为镜像准备者，我希望每次提交只对应一个发行版本和目标平台，以便分别了解进度、取消与结果。
29. 作为镜像准备者，我希望后续下载项能参与共享并发，以便不被前一个下载项整体阻塞。
30. 作为镜像准备者，我希望同一目录中的重复文件及版本级附件只获取一次，以便节省网络流量和磁盘写入。
31. 作为镜像准备者，我希望不同输出目录的任务保持各自绑定，以便修改当前目录不把已有任务迁移到其他位置。
32. 作为镜像准备者，我希望查看下载项汇总与单文件进度，以便区分排队、下载、校验、保存和已满足。
33. 作为镜像准备者，我希望全局下载量不重复累计复用文件，以便看到真实传输量。
34. 作为镜像准备者，我希望单独取消某项下载而不影响其他项所需文件，以便调整计划而不误停其他工作。
35. 作为镜像准备者，我希望取消后看到“仍用于其他下载”的解释，以便理解为什么关联文件还在继续。
36. 作为镜像准备者，我希望仅在未完成文件没有被其他下载使用时单独取消文件，以便不会误停多项下载。
37. 作为镜像准备者，我希望安全保存或索引阶段的取消显示等待步骤，以便知道取消处理中而不是失效。
38. 作为镜像准备者，我希望取消保留已校验正式文件，以便不会丢失已经准备好的内容。
39. 作为镜像准备者，我希望失败后手动从头重试，以便自主决定是否再次使用网络和磁盘。
40. 作为镜像准备者，我希望一个文件失败不阻断其他独立任务，以便保留部分成功结果。
41. 作为镜像准备者，我希望异常说明原因、受影响内容和下一步动作，以便知道哪些工作还能继续。
42. 作为镜像准备者，我希望归档严格通过官方 SHA-256 校验后才成为正式文件，以便未完成或损坏内容不会被宣称可用。
43. 作为镜像准备者，我希望原样保留官方 `SHASUMS256.txt` 和提供的签名附件，以便保留客户端所需的校验依据和原始附件。
44. 作为镜像准备者，我希望附件获取告警与归档完整性失败分别呈现，以便不会把附件失败误当成所有内容不可用或 PGP 验证成功。
45. 作为镜像准备者，我希望已有管理镜像中的有效文件重新核验后复用，以便避免重复下载且不盲目信任历史记录。
46. 作为镜像准备者，我希望同路径冲突、损坏或无法安全核验时保留原文件并停止对应操作，以便不被静默覆盖或删除。
47. 作为镜像准备者，我希望应用不自动接管手工拼装的非空目录，以便保护未知内容。
48. 作为镜像准备者，我希望磁盘空间不足、目录不可写或失联时只停止依赖该条件的操作，以便其他目录继续工作。
49. 作为镜像准备者，我希望目录移动后由我重新指定并核验，以便应用不猜测路径或创建替代镜像。
50. 作为镜像准备者，我希望上游文件名和相对路径原样保存且不解压，以便之后按相对路径上传并供客户端消费。
51. 作为镜像准备者，我希望镜像索引只来自实际齐备且校验通过的内容，以便消费者不会发现从未下载的发行版本。
52. 作为镜像准备者，我希望某发行版本仅有一个目标齐备时也能收录，以便无需补齐所有目标平台才形成部分镜像。
53. 作为镜像准备者，我希望只下载部分平台时明确列出真正可用目标，以便不把版本发现当成所有目标都能安装的承诺。
54. 作为镜像准备者，我希望追加内容后重新生成索引，以便镜像发现结果反映新增文件。
55. 作为镜像准备者，我希望外部删除或修改文件后撤下受影响声明但保留其他有效平台，以便不发布失实可用性信息。
56. 作为镜像准备者，我希望同根索引协调串行、内容先于索引发布，以便并发下载不产生半写入或丢失声明的索引。
57. 作为镜像准备者，我希望索引失败时保留正式文件和旧索引并提供手动重新核验，以便修复一致性而不丢失数据。
58. 作为镜像准备者，我希望按镜像根目录区分下载结果与可交付状态，以便不会把文件成功误当成镜像已可上传。
59. 作为镜像准备者，我希望全部相关写入结束且索引一致后能交付有效子集，以便部分失败不阻止其他内容使用。
60. 作为 nvm 使用者，我希望用一个镜像根 URL 发现镜像子集，以便两个约定客户端共用同一份导出内容。
61. 作为 nvm 使用者，我希望本机目标文件齐备时能精确安装发行版本并运行 `node --version`，以便验证实际可消费而不是只有路径相似。
62. 作为 nvm 使用者，我希望知道 latest、LTS 和主版本选择来自共享镜像子集，以便不把镜像最新等同于官方最新。
63. 作为 nvm 使用者，我希望了解合并索引可能发现只有其他平台文件的发行版本，以便正确理解别名选中本机不可安装发行版本的限制。
64. 作为镜像准备者，我希望关窗、菜单退出和退出快捷键走同一流程，以便没有隐蔽的后台下载。
65. 作为镜像准备者，我希望最小化不停止任务，以便在处理其他工作时继续下载。
66. 作为镜像准备者，我希望有任务时先看到退出影响并能选择继续下载，以便不因误关窗口停止工作。
67. 作为镜像准备者，我希望确认停止后所有输出目录停止派发新工作并完成必要安全步骤，以便不残留半提交文件或不一致索引。
68. 作为镜像准备者，我希望等待退出时看到具体文件、目录与步骤，以便知道应用为什么还未退出。
69. 作为镜像准备者，我希望索引协调失败时保存未完成状态后可以明确选择退出，以便不必先修好目录才能离开应用。
70. 作为镜像准备者，我希望无法保存状态或写入尚未结束时不被告知安全退出成功，以便不会误信数据已得到保护。
71. 作为镜像准备者，我希望重开区分“已停止（应用退出）”和“已中断”，且不自动联网或协调索引，以便自主决定恢复动作。
72. 作为镜像准备者，我希望重开保留未完成下载项的目录、文件关联与已有结果，以便了解剩余工作而不需要完整历史系统。
73. 作为内部使用者，我希望看到首次打开、安全提示和 WebView2 安装失败的说明，以便按系统与组织允许的方式使用应用。
74. 作为内部使用者，我希望手动升级及卸载默认保留应用数据和镜像，以便不会失去已准备的文件和恢复信息。
75. 作为内部使用者，我希望不兼容或损坏状态被保护且启用空状态需确认，以便不会被静默清空或自动执行错误任务。
76. 作为验收者，我希望规划完成、开发完成与验收通过分别记录，并有自动化、原生安装包和真实客户端证据，以便知道实际兑现了哪些承诺。

## Implementation Decisions

### 1. 技术路线、Module 与权威状态

- 前端采用 React + TypeScript，桌面宿主采用 Tauri 2，后端采用 Rust。第一版采用单个 Tauri/Rust crate，以内部 Module 划分任务编排、Node.js 领域规则、上游分发源、镜像文件操作及 JSON 状态存储，不拆多个 crate。
- Rust 持有权威下载请求、文件任务和镜像可用性状态；前端仅维护展示状态与未提交选择，不通过界面推测“校验通过”“已满足”或“可交付”。
- 应用 Module 对界面的 Interface 包含操作命令、状态快照及通知：命令请求操作和查询快照，Channel 传递高频有序进度，Event 传递轻量通知。前端重新连接后从权威快照重建展示，不只依赖曾收到的通知。
- 底层传输及文件操作可以复用；发行版本、发布线、LTS、文件识别、目标必需格式与镜像索引属于 Node.js 领域。第一版不建设通用运行时插件框架，不实现 Python/Go Adapter。
- 为网络与镜像文件操作保留窄 Interface，由生产与测试 Adapter 满足；不为每个函数增加抽象。领域规则可用固定数据及明确查询日期验证，实际文件行为通过临时目录验证。

### 2. 固定来源与权限

- Node.js 上游版本目录与分发文件来源固定为 `https://nodejs.org/dist/`；官方目录可提供下载候选元数据，官方 Release Working Group 的 `schedule.json` 提供发布线生命周期依据。
- 每次提交一个结构化发行版本、一个系统/架构目标，以及用户通过目录选择器明确选定的输出根目录。格式和官方辅助附件由 Rust 中的领域规则确定，不接受前端提供任意格式、任意 URL 或自定义镜像地址。
- Rust 构造官方文件 URL，验证发行版本、受支持目标及官方清单中的相对路径，验证写入目标位于选定输出根目录内的 `nodejs/`；不得因路径文本看似正确就放弃目录越界及同路径文件保护。
- Tauri 权限采用最小范围；插件目录 scope 不代替自定义 Rust 命令的业务校验。应用不以管理员身份运行，不修改 nvm、PATH、文件关联或系统安全设置。
- 不硬编码调研时的“最新”发行版本、LTS 主版本或具体依赖版本。工具链、依赖及构建参数由实现阶段在已定产品约束内核实并锁定。

### 3. 上游版本目录、搜索与 LTS

- 验证上游所需元数据，区分发行版本与发布线、发行版本 LTS 标记与发布线支持状态。上游目录的 `files` 是官方文件类别，不足以枚举所有具体格式或证明文件存在。
- 搜索先去除首尾空白，再移除可选前导 `v`，兼容大写 `V`；按去前导标记的版本号文本前缀匹配。`22.1` 可匹配 `22.10`，不是语义版本范围查询。结果按语义版本降序，不按字符串或发布日期排序。
- 发行版本单选。搜索、LTS 筛选、生命周期刷新或日期变化使所选发行版本不再匹配时，清除发行版本选择，保留系统与架构，不自动改选；已提交下载请求不变。
- 当前受支持 LTS 要求发行版本具有有效非空 LTS 标记，且所属发布线具备有效生命周期数据，在当前 UTC 日期处于 `[lts, end)`。`lts` 当日开始受支持，`end` 当日开始不再受支持；Active LTS 与 Maintenance LTS 都包含。UTC 半开区间是应用约定，不宣称官方给出了精确转换时刻。
- 不使用偶数主版本、静态版本列表、客户端 LTS 别名或单独 `lts != false` 代替上述判断。缺失或无效数据不得通过猜测补全。
- 版本目录与生命周期分别缓存，有效期分别为 1 小时与 5 分钟；过期后下次打开应用时刷新，并提供手动刷新，使用 ETag 条件请求。缓存时长属于应用策略，不是上游 SLA。
- 每次计算当前受支持 LTS 都按当前 UTC 日期重判，UTC 跨日自动更新；仍有效的时间表不因跨日单独重下载，取得更新后立即重判。缓存过期且无法刷新、缺失或无效时，相关支持状态为未知，不沿用过期值宣称仍受支持。
- 未启用 LTS 筛选时，在信息足以识别发行版本的情况下展示未知状态；启用筛选时排除未知项并提示结果不完整。明确为非 LTS 的发行版本仍按非 LTS 排除，不因时间表失效改称受支持。
- 列出受支持发布线内全部带 LTS 标记的符合条件发行版本，标记每条发布线的最新发行版本。选择旧补丁时提示可能不包含后续安全更新，不据此断言该发行版本不安全。
- 计算依赖本机系统时间并明确提示；不接入独立授时、不自动校时、不承诺校验本机时钟。

### 4. 目标平台与提交交互

- 系统范围为 macOS、Windows、Linux，架构为 x64、ARM64，形成六个目标组合；下载器自身运行平台不限制目标范围。范围内下拉选项始终可浏览，不展示支持比例。
- Linux 仅采用标准 `linux-x64` / `linux-arm64`，不限定 Debian 等具体发行版；排除所有 musl 变体。不提供变体开关、格式选择、任意可选格式追加或范围外诊断列表。
- macOS/Linux 必需格式固定为 `.tar.xz` 与 `.tar.gz`，Windows 固定为 `.7z`。ZIP、安装器、源码及其他目标的文件不能替代必需格式；不自动补齐未选择的目标平台。
- 仅在成功取得并解析该发行版本的官方 `SHASUMS256.txt` 后判断必需文件存在性。不从系统/架构/格式笛卡尔积生成“必定存在”的下载候选，不仅凭索引类别判断格式齐备。
- 未选发行版本、清单未就绪或获取/解析失败、任一必需文件缺失时禁用下载。清单错误显示明确原因和用户主动重试入口，不冒充目标不支持；其他清单正常的发行版本不受影响。
- 页面显示当前发行版本、目标平台、必需输出文件和输出目录。无输出根目录时，有效选择点击下载先打开目录选择器；取消不创建下载请求或文件任务，并保留选择。目录确定后直接入共享队列，不增加下载确认对话框。
- 无下载确认不等于允许覆盖：已有路径冲突仍停止并提示，不提供正式文件重置或替换能力。

### 5. 下载请求、去重与调度

- 一次提交是一个下载请求，对应一个发行版本与一个目标平台；界面称为一项“下载”。请求绑定提交时明确选择的输出根目录，改变当前选择不迁移已提交请求。
- 所有下载请求进入同一个共享、有界并发的文件任务队列。请求分组只用于汇总和取消，不形成串行屏障；后续请求可与先前请求并发。具体并发上限由实现及测试调整，不照搬原型的三槽。
- 相同镜像根目录和官方相对路径对应的具体文件任务跨提交复用；发行版本级清单与签名附件也复用。不将不同输出目录中的同名文件当成同一个已满足文件，也不暗示多人共享。
- 显示下载项汇总及关联文件进度；文件状态涵盖排队、下载、校验、正式文件提交、已满足、失败和已取消等可观察阶段。下载项结束、文件成功或进度满格不等于目标齐备或镜像可交付。
- 请求可引用同一个文件任务。全局传输量只计实际唯一文件传输，不把每个请求对复用文件的进度重复累计。
- 一个任务失败不阻断其他独立任务。目录不可用或无法安全协调索引等共享故障，只停止依赖该条件的操作，其他目录的独立工作继续。
- 支持用户手动重试失败或未完成项，从头下载；不自动重试，不支持暂停、断点续传或重启自动下载。

### 6. 取消与异常反馈

- 取消一项下载撤销该请求的有效需求引用；只停止没有其他下载仍需的未完成文件。仍用于其他下载的文件继续，界面说明“此下载已取消；这个文件仍用于你的另一项下载”。
- 没有被其他下载使用的未完成文件可单独取消；仍用于多项下载时不提供能停止所有相关下载的单文件取消入口。页面不提供取消全部队列，也不暴露“停止所有引用方”能力。
- 已校验正式文件保留。正式文件提交或索引更新期间取消，先完成必要安全及一致性步骤，再结束取消；显示“取消处理中”及具体等待步骤。
- 必要索引协调失败时，保留正式文件和旧索引，说明取消仍等待一致性恢复，提供主动重新核验/协调，不声称镜像可交付。
- 每个异常说明原因、受影响文件/下载项/目录、仍可继续的内容和下一步。清单失败须说明归档不能完成校验，不误报目标缺文件。
- 冲突、损坏或不能安全核验须用户在应用外处理；应用不提供覆盖、删除、重置或替换正式文件入口，重试也不能绕过保护。
- 空间不足、目录不可写或失联时停止受影响工作，条件恢复后不自动重启；用户主动重试。不自动猜测目录、改绑或创建替代镜像。
- 分别呈现“部分文件成功，此目标尚不齐备”、签名附件告警及“文件已保留，索引未确认，尚不可交付”，不把这些不同结果合并为一个成功状态。

### 7. 文件完整性、目录管理与持久化

- 输出为用户选定输出根目录内的 `nodejs/`，保留官方原始文件名和版本目录相对路径；不解压、不改名、不执行分发内容。
- 新建镜像要求 `nodejs/` 不存在或为空。已有应用管理记录的镜像可以追加，不自动接管手工拼装的非空目录；未登记文件不自动收录或删除。
- 管理记录与临时下载内容位于 `nodejs/` 外，不污染未来上传的镜像。临时目录布局及文件提交机制由实现决定，但须满足同文件保护、完整写入和平台故障约束，不能假定任意 rename 天然无覆盖且跨文件系统原子。
- 官方 HTTPS 获取的 `SHASUMS256.txt` 原样保留字节，可含未下载条目；清单用于预期 hash，不作为可用内容列表。每个归档须匹配清单中的对应路径及 SHA-256，才可成为正式文件；网络成功或大小正常不够。
- 获取并原样保存官方提供的 `.asc`、`.sig` 附件，如有；获取失败单独告警，不阻止其他条件满足的内容收录。不生成官方签名，不执行 PGP 验证，不声称发布者真实性已独立验证。
- 已管理镜像中的已有文件经重新核验且匹配官方依据后可视为已满足；不匹配、冲突或无法安全核验时停止对应项并保护原文件。已有正式文件不因新任务失败、取消或退出而删除。
- 只清理能够确认归应用管理的未完成临时文件；失败或取消的临时文件可清理。异常退出后，仅在用户重新选择相应已管理镜像并主动重试时，按管理记录处理可确认的孤立临时文件；不触碰未知或正式文件。
- 任务绑定明确选择的目录。目录移动或不可用时停止并提示；重新指定后重新核验，不能仅凭历史路径或成功记录自动改绑。
- 用户级应用数据目录保存带格式版本的 JSON 状态，记录输出目录、共享文件任务及下载请求关联、待处理/失败/可重试/中断工作和镜像索引未确认状态。状态记录不是镜像可用性的证明。
- 为恢复尚需处理的下载项，保留其绑定目录、文件关联及已完成、失败、此前取消的结果；重启不把这些既有结果一律改成停止或中断。不建设或保存无限累积的完整完成历史，具体状态字段及清理策略不得丢失仍需恢复的关联与结果。
- 状态不兼容、不可识别或损坏时，保护原文件并明确提示，不静默清空、覆盖或执行旧任务；经用户确认可启用新的空任务状态，不因该操作删除镜像。

### 8. 部分镜像索引与交付条件

- 所有目标共用一个镜像根入口，只生成约定客户端消费的共享 `index.tab`，不生成分平台入口、旧版 `index.json` 或 `latest/` discovery 内容。
- 某发行版本至少一个已选择目标的必需文件全部成为校验通过的正式文件，且具有对应官方校验清单，才可收录。不要求其他目标齐备或所有请求成功；只有零散文件、不齐备必需格式或额外可选文件不能使尚无可安装目标的发行版本收录。
- 索引保留客户端所需官方表头与字段结构，包括官方日期、npm、LTS 名称及其他事实字段；按语义版本降序。`files` 按官方类别映射如实表达已完成且校验通过的实际文件，不复制上游全量类别、不虚构类别；类别列不替代格式齐备判断。
- 上游全量目录只供候选和内部缓存，不能直接作为镜像索引。已登记可用内容是索引事实来源，未登记文件不自动收录。
- 每次索引更新前重新核验支撑声明的全部必需文件及 SHA-256，不只检查新增内容。文件被外部修改或删除时撤下受影响平台；仍有其他齐备目标时保留该发行版本，否则撤下索引行。文件类别声明也不能沿用未经核验的旧结果。
- 下载仍可并发，同一镜像根目录的索引更新协调串行；先提交已校验正式内容及清单，再完整替换索引，不发布半写入索引。协调须考虑同时追加的内容，不能让旧协调结果覆盖新的事实。
- 索引生成或写入失败时保留正式文件和旧索引，标记索引未确认、尚不可交付；用户可主动重新核验及协调。旧索引被保留不代表仍准确，不将该状态宣传为可交付。
- 按镜像根目录显示真实齐备目标、索引状态、未完成项及告警。该根存在任何未完成写入时不可交付；全部相关写入结束、内容重新核验且索引一致后，有效子集可交付，不要求全部下载项成功。
- 不因 LTS 筛选或发布线 EOL 自动删除文件、改写官方 LTS 标记或撤下仍满足可用条件的索引行。
- 向未来上传流程交付时停止该镜像根写入，以 `nodejs/` 内相对路径为上传基准；内容与校验文件先于索引发布。本阶段不实现上传、快照、远端事务或部署。

### 9. nvm 消费契约与已接受限制

- 固定兼容对象为 `nvm-sh v0.40.8` 和 `nvm-windows v2.0.1` 的标准在线二进制安装；不承诺旧版客户端、源码构建或完全离线。
- 消费入口指向实际镜像内容根，约定匿名 HTTPS 只读访问明确的索引、清单与归档 URL；不依赖目录 HTML、软链接、交互登录或额外下载认证设置。未来上传认证与下载匿名是不同要求。
- 合并索引表达“至少一个目标可安装的发行版本并集”，不是每个客户端本机可安装集合。接受客户端发现只有其他平台文件的发行版本；裁剪 `files` 不构成可靠的本机平台发现过滤承诺。
- 精确二进制安装要求镜像具备客户端本机实际请求的必需内容及清单；缺文件时不承诺回源、补齐、换镜像、源码构建或自动寻找本机适用的次新发行版本。
- latest、LTS、主版本等选择由客户端依据镜像子集解析，不追随未下载的上游最新。镜像最新不等于官方最新，客户端 LTS 别名不等于应用的当前受支持 LTS。
- 客户端可能缓存索引，不承诺更新立即对所有客户端生效。外围联网允许存在，但不能掩盖镜像缺文件或被宣传为完全离线兼容。

### 10. 正常关闭、全局停止与恢复

- macOS/Windows 的主窗口关闭、最后一个窗口关闭、菜单退出及退出快捷键进入同一个退出流程；不关窗后后台下载、不加托盘或后台服务。最小化继续运行；不提供下载完成后自动退出。
- 没有排队或进行中工作，也没有待处理镜像一致性问题时直接退出。普通失败、取消或签名附件告警本身不触发索引未确认警告。
- 有排队、下载、校验、正式文件提交或索引协调时先提示影响所有输出目录的未完成工作，提供“继续下载”和“停止并退出”；说明正式文件保留、重开不自动续传且未完成文件需手动从头重试。
- 提示期间任务继续；选择继续或关闭提示仅放弃本次退出，不改变队列。确认停止后不派发新任务、不接受新提交与重试，中断可安全中断的下载/校验，不为退出下载剩余文件。
- 退出是全局停止，作用于所有目录；唯一共享文件任务只停止或收尾一次，不在下载页面新增取消全部队列能力。
- 已进入正式提交或索引替换的工作完成必要安全步骤，对已提交有效内容完成必要一致性处理，不在写入中途截断。显示“正在停止并安全退出”及具体文件、目录和步骤。
- 确认停止后不提供恢复原队列的撤销退出。返回应用仅放弃退出意图，已停止工作不自动恢复，已经开始的安全收尾继续，限制与尚未结束收尾冲突的操作。
- 重复退出请求复用现有流程，不创建第二套收尾或跳过等待。长等待说明原因与路径，不以固定超时强杀。
- 各镜像根分别报告收尾结果，一个目录失败不阻止其他目录安全收尾。整体安全退出要求所有相关写入结束且应用状态保存成功。
- 文件已保存而索引失败时保留文件和旧索引，标记受影响根索引未确认。无进行中写入且成功保存需重新核验/协调的未完成状态后，提供“返回应用处理”和“保留未完成状态并退出”；后者须明确选择，不要求先修好目录，也不静默退出。
- 状态无法保存或写入尚未结束时，不报告安全退出成功，说明失败或等待并允许返回应用，不提供绕过步骤的强制退出按钮。
- 空闲但仍有索引一致性问题时，列出目录并提供“返回应用”和“仍然退出”；退出同样要求无进行中写入、状态成功保存和用户确认。
- 重开将正常退出停止的未完成工作显示为“已停止（应用退出）”，异常遗留显示为“已中断”；不自动启动下载或未完成索引协调。已完成、失败、此前取消结果保留，状态记录仍不能证明磁盘有效。
- 用户重新选择对应已管理镜像并主动重试，从头下载；已有正式文件重新核验后才复用。索引未确认根继续不可交付，用户主动核验与协调。
- 系统强制结束、关机或其他中断按异常退出处理，不承诺阻止这些操作，不计为安全退出成功。

### 11. 内部桌面交付

- 面向本人及少量内部使用者，不公开发布、不进应用商店。运行组合为 macOS Apple Silicon、macOS Intel、Windows x64；支持下限为 macOS 13、Windows 10 22H2 / Windows 11，不承诺更老系统或任意受管设备可运行。
- macOS 分架构 DMG，用户将 `.app` 放入 Applications，不做 Universal；Windows x64 当前用户 NSIS `.exe`，不另做 MSI 或便携版。macOS/Windows 分别原生验证及打包，不承诺仅在 macOS 完成全部 Windows 构建。
- macOS 内部版采用 ad-hoc 签名，暂不要求 Developer ID 或公证；Windows 内部版暂不要求发行者代码签名。接受可能的系统提示，不声称系统已认可发行者或保证无提示。
- 提供首次打开说明，macOS 仅在用户信任且系统允许时说明逐应用 Privacy & Security 流程，Windows 说明实际提示和限制；不要求全局关闭安全保护，不承诺绕过恶意判定、撤销或组织策略。
- Windows 检测复用 WebView2，缺少时通过官方 bootstrapper 联网安装，不携带离线安装器/固定运行时。依赖安装失败明确报告并提供官方指引，不宣称已可用；应用当前用户安装不保证依赖在所有环境无需额外授权。
- 只安装应用及必要运行时，不设开机启动、后台服务、PATH 或文件关联。Windows 提供普通启动和卸载入口，macOS 常规移除 `.app`；不自动清理镜像。
- 不做应用内自动更新或联网检查应用更新；使用者手动获取安装包升级。升级前结束工作并退出旧版，不热升级或静默强杀，占用时要求退出或阻止替换。
- 升级保留用户级应用数据，卸载默认保留应用数据和输出目录镜像。稳定应用数据身份及安装/卸载行为需实现与验证，不能凭默认行为推断；后续变更数据路径须有迁移安排。
- 状态格式带版本；不承诺任意旧版迁移或降级兼容。升级重开不自动联网，损坏状态保护与经确认启用空状态遵循前述规则。
- CI、具体框架与机器分配属于实现安排，不在本规格配置 CI/CD、证书、密钥或发布账号。

## Testing Decisions

### 1. 测试原则与接缝

- 好的测试验证调用者及消费者可观察行为：命令是否被接受、权威快照/通知、真实文件内容与路径、索引声明、数据是否保留，以及客户端发现/安装/运行结果。不绑定私有函数、内部状态枚举拼写、线程顺序或某个库的调用次数。
- 主要自动化测试跨应用 Module 的命令/快照/通知 Seam，覆盖多个内部 Module 联动；不把领域、队列、文件和索引拆成互相 mock 的浅测试。
- 沿用已决的网络与镜像文件操作内部 Seam，使用受控生产/测试 Adapter 注入网络、校验、权限与写入故障。真实文件行为结合新建临时目录测试，尤其是原文件保护及内容先于索引；不以全内存文件模拟代替所有磁盘测试。
- 领域规则使用固定目录/清单/时间表及明确查询日期测试，不为此新增通用时钟框架。界面验证通过正式应用的用户操作及权威结果，原生窗口/退出/安装行为在实际安装包中验证。
- 仓库尚无正式应用或自动化测试套件。两个内存 HTML 原型中的选择动作与队列情景是测试场景 prior art，不是生产实现或通过证据；演示三槽与手动协调不能作为正式约束。具体测试框架留给实施者。

### 2. 搜索、目录与生命周期自动化

- 覆盖首尾空白、`v`/`V`、空查询、`22.1` 匹配 `22.10`、数值版本降序及发行版本单选。
- 覆盖搜索/LTS 状态失配清除发行版本、保留目标、不自动改选、不影响已提交请求；原生目录选择取消不创建任务。
- 用同一发布线的 LTS 与进入 LTS 前发行版本、历史 EOL、Active/Maintenance、未知/缺失/无效记录，证明发行版本标记与发布线状态分离。
- 覆盖 UTC `lts` 当日前/当日、`end` 前一日/当日、跨日自动重判、时间表更新立即重判；无需跨日重复下载有效缓存。
- 覆盖独立 1 小时/5 分钟缓存、打开时过期刷新、手动刷新及 ETag 条件响应；过期刷新失败呈现未知与筛选不完整，不硬编码主版本或沿用过期受支持声明。
- 覆盖每条发布线最新标记、旧补丁提示及本机时钟依赖说明。
- 覆盖六目标与固定必需格式，musl/范围外候选不展示或下载；缺少其中一种归档不允许提交。清单未就绪/获取或解析失败与成功清单证明缺文件必须分别呈现，其他发行版本不被误阻断。
- 覆盖结构化输入校验、固定来源及所选目录范围，非法发行版本/目标/相对路径不能绕过后端规则。

### 3. 队列、取消与文件保护硬门槛

- 在不同提交同时存在时验证有界并发和后提交能够推进，不要求固定的调度顺序；同根同路径、清单和附件只实际获取一次，不同根不被错误去重，全局传输量不重复累计。
- 覆盖取消一项共享下载、无其他需求时停止、其他需求继续、单文件取消入口限制和解释文案；安全提交/索引阶段取消必须完成必要步骤，失败不误报取消完成与可交付。
- 覆盖首次下载、追加、网络中断、清单失败、SHA-256 失败、签名附件失败、部分结果、主动重试、异常退出/重开。验证无自动重试、暂停、续传或重启自动联网。
- 受控小型文件证明 hash 不匹配或未完成内容不能进入正式文件/索引；清单原始字节不被裁剪，签名附件只保存而不显示 PGP 通过。
- 覆盖已管理有效文件重新核验复用、同路径未知/冲突/损坏文件、无法安全核验、非管理非空目录、不可写/失联目录、空间不足及目录变更。验证原文件/未知内容不被覆盖、删除或接管，重试不能绕过保护。
- 检查取消/失败/手动恢复只清理可确认的应用临时内容，正式及未知文件保留；管理记录和临时内容不进入镜像根。
- 不以操作成功的事件或历史状态代替磁盘事实。通过内容、存在性及原文件对照证明数据保护。

### 4. 索引、一致性与恢复硬门槛

- 至少一个目标必需文件齐备才收录发行版本；零散成功不够。不照搬上游全量索引，不虚报未下载目标，语义版本降序及官方字段/类别结构满足客户端。
- 覆盖同一发行版本一平台失败而其他平台齐备、某下载项失败而既有内容有效，证明部分成功可交付的条件不等于全部请求成功。
- 每次索引协调重新核验既有内容；外部删除/修改导致受影响声明撤下，其他有效目标继续保留，磁盘文件不被自动修复/删除。LTS/EOL 不自动撤下仍有效内容。
- 注入同根并发追加与索引更新，验证协调串行、旧结果不覆盖新增事实、内容先于完整索引替换；下载保持可并发。
- 注入索引生成/写入失败及协调中断，验证保留正式文件和旧索引、不可交付提示及手动重核验。镜像根任何未完成写入期间不可交付；全部结束且一致后有效子集可交付。
- 重开不自动下载或协调，状态/历史不直接证明可用；主动恢复需重新选择已管理镜像、重新核验正式内容，从头重试未完成文件。
- 覆盖不兼容/损坏 JSON，原文件保护及明确提示，经确认启用空状态不删除镜像；恢复关联结果保留，不要求完整无限历史。

### 5. 正常退出测试

- 自动化与原生安装包均覆盖空闲关窗、最后窗口、菜单/快捷键统一退出及最小化继续；普通失败/取消/附件告警不能误触发索引未确认警告。
- 退出提示期间任务继续，继续或关闭提示不改变队列；确认停止后阻止新派发/提交/重试，不自动恢复已停止工作。
- 在排队、下载、校验、提交及索引阶段退出，覆盖共享文件、多根目录、重复退出及清晰等待反馈，不在安全写入中途截断。
- 覆盖索引失败、目录失联、状态保存失败、长等待、返回应用及明确保留未完成状态退出。无状态成功保存或仍有写入时不能报告安全退出，不提供强制跳过或固定超时强杀。
- 覆盖空闲索引未确认提醒；正常退出重开显示“已停止（应用退出）”，异常/系统强制中断重开显示“已中断”，既有完成/失败/取消结果不一律重写。无自动联网/协调、手动重试及未知文件保护必须继续成立。

### 6. 真实 nvm 消费最低矩阵

| 固定客户端 | 消费环境 | 必须真实消费的格式 |
| --- | --- | --- |
| `nvm-sh v0.40.8` | macOS x64 | 分别验证 `.tar.xz`、`.tar.gz` |
| `nvm-sh v0.40.8` | macOS ARM64 | 分别验证 `.tar.xz`、`.tar.gz` |
| `nvm-sh v0.40.8` | 标准 Linux x64，非 musl | 分别验证 `.tar.xz`、`.tar.gz` |
| `nvm-sh v0.40.8` | 标准 Linux ARM64，非 musl | 分别验证 `.tar.xz`、`.tar.gz` |
| `nvm-windows v2.0.1` | Windows x64 | `.7z` |
| `nvm-windows v2.0.1` | Windows ARM64 | `.7z` |

- 每个组合经可控匿名 HTTPS 静态服务消费生成的实际镜像，验证版本发现、精确二进制安装及实际执行 `node --version` 等于所选发行版本。测试发行版本必须由官方清单确认对应必需文件齐备。
- nvm-sh 通过客户端工具环境控制 xz/gzip，不改客户端源码；请求日志证明实际获取及使用对应归档。协议模拟、路径检查或 HTTP 内部测试不能替代最终 HTTPS 真实消费。
- 允许虚拟机，但必须实际安装和运行对应架构 Node.js。Windows ARM64 是消费环境，不新增下载器安装包；Linux 消费不新增 Linux 桌面应用。具体系统、Linux 发行版、工具环境及测试发行版本执行时固定并记录，不穷举历史发行版本。
- 使用独立或明确处理缓存的环境，发现列表来自镜像子集而非全量上游。记录缓存前提，不要求索引更新立即对所有客户端生效。
- 两个客户端均覆盖部分平台镜像、精确安装、客户端支持的 latest/LTS/主版本选择及缺本机文件的边界。别名按共享子集解析，本机文件齐备时安装；只有其他目标内容时接受发现及别名选中不可安装发行版本，不要求自动次新回退。
- 缺文件不能以回源、切换镜像或源码构建后的成功算本镜像通过；记录解析结果、请求和失败/回退行为。索引、所需清单与归档须来自测试镜像，外围联网不能掩盖缺内容。
- 证据记录固定客户端版本、系统/架构、格式环境、镜像子集、操作、解析、安装/运行结果及 HTTPS 请求日志。缺任一环境或格式记为待验证，失败记为失败，不宣布全矩阵通过。

### 7. 原生桌面交付验收

- 使用实际 DMG/NSIS 安装包，验证 macOS Apple Silicon、macOS Intel、Windows x64，并覆盖 macOS 13、Windows 10 22H2 / Windows 11 基线；开发模式不能替代。
- 验证安装、首次打开、主界面、原生目录选择和正常关闭/退出；记录实际安全提示，不把绕过系统/组织策略作为目标。
- Windows 分别验证已有 WebView2、缺少后安装及依赖安装失败的报告/官方指引，不能失败后仍报告已可用。
- 验证无管理员方式运行、仅在选定目录写镜像、不加开机启动/后台/PATH/文件关联，不修改 nvm。
- 验证退出旧版后手动升级、占用时阻止替换、数据身份稳定、升级保留状态及镜像、卸载保留应用数据和镜像；升级后无自动联网。
- 验证不兼容/损坏状态保护、用户确认启用空状态及镜像不受删除影响。缺环境记为待验证，不穷举全部系统补丁。

### 8. 完成与证据

- 规划完成、开发完成、验收通过分别记录。调研、原型、源码静态检查、开发模式或下载列表成功都不是正式验收替代品。
- 第一版验收通过必须同时具备领域与故障自动化、数据保护/索引/退出硬门槛、实际安装包原生验证及真实客户端最低矩阵证据。
- 每项验收关联本规格预期，记录环境、步骤、结果与证据；未执行、缺环境、失败明确列出。不用“准备好执行”或 `ready-for-agent` 宣称已经通过。
