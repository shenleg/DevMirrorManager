# 18: 按当前受支持 LTS 筛选发行版本

**What to build:** 用户可按当前受支持 LTS 筛选候选，理解发行版本标记、发布线支持状态、未知信息和旧补丁提示；生命周期刷新及 UTC 跨日会更新筛选和未提交选择，不影响已提交下载。

**Blocked by:** 15 — 按目标平台预览真实必需文件。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 依据官方 Release Working Group 生命周期数据及发行版本自身有效非空 LTS 标记判定，不仅依赖标记、奇偶主版本、静态列表或客户端 LTS 别名。
- [ ] 当前 UTC 日期在发布线 `[lts, end)` 才受支持：LTS 开始当日包含，结束当日排除，Active 与 Maintenance LTS 都包含；明确该日期解释是应用约定。
- [ ] 生命周期独立缓存 5 分钟，与版本目录 1 小时缓存分离；过期后下次打开刷新，支持主动刷新及 ETag 条件请求。
- [ ] 每次计算按当前 UTC 日期重判，跨日自动更新，取得新时间表立即重判；有效缓存不因跨日单独重新下载。
- [ ] 缺失、无效或过期无法刷新时，相关支持状态未知，不沿用旧受支持结论。未启用筛选可展示可识别发行版本的未知状态，启用筛选排除未知并提示结果不完整；明确非 LTS 仍排除。
- [ ] 搜索、筛选或生命周期变化导致所选发行版本失配时，仅清除发行版本、保留系统/架构、不自动改选；接入已有下载请求后证明其不受候选变化影响。
- [ ] 显示每条发布线最新发行版本，选择符合筛选的旧补丁时提示可能缺少后续安全更新，不断言旧补丁必然不安全。
- [ ] 提示判定依赖本机系统时间，不加独立授时、自动校时或时钟准确性承诺；筛选及 EOL 不删除镜像、改写官方标记或自动撤下有效镜像索引。
- [ ] 固定目录/生命周期与查询日期经应用 Interface 覆盖 LTS 标记与发布线分离、EOL、未知、UTC 起止边界、跨日、刷新失败与缓存条件响应。
- [ ] 在正式界面演示筛选、未知降级、旧补丁及失配清除，不为测试引入通用时钟框架；可与下载链路并行实现。
