# 23: 重启后展示未完成工作并手动恢复

**What to build:** 用户重开应用后能看到尚需处理的下载项、绑定目录及已有结果，而非自动恢复网络；主动重新选择已管理镜像、重新核验和从头重试。损坏或不兼容的状态受到保护，重置任务状态不删除镜像。

**Blocked by:** 20 — 取消下载项而不误停其他下载；21 — 解释下载故障并支持手动从头重试；22 — 安全追加、重新核验与恢复镜像索引一致性。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 用户级稳定应用数据身份下保存带格式版本 JSON，记录输出目录、共享文件任务/下载请求关联、待处理/失败/可重试/中断工作以及索引未确认状态；管理记录不混入镜像内容。
- [ ] 重开将异常退出遗留的未完成工作标为“已中断”，已完成、失败及此前取消结果不一律重写；保留尚需恢复下载项的关联结果，不建立无限完整完成历史。
- [ ] 重开不自动下载、重试或执行未完成索引协调；上游候选正常刷新与恢复下载分开，不把“不自动联网”误用为禁止既定目录刷新。
- [ ] 用户主动恢复需要重新选择对应已管理镜像；绑定路径不可用时提示，不猜测、改绑或创建替代镜像。正式文件重新核验官方依据后才复用。
- [ ] 未完成文件手动从头重试，无断点续传；仅在确认应用管理归属时处理孤立临时内容，不触碰正式及未知文件。
- [ ] 索引未确认的目录重开仍不可交付，用户主动重新核验/协调；状态文件与历史成功不能直接证明当前磁盘可用。
- [ ] 状态不可识别、格式不兼容或损坏时保护原文件，显示明确错误，不自动执行旧任务、清空或覆盖。
- [ ] 经用户确认可启用新空任务状态，取消确认保留原状态；原状态保护策略可由实现选择，但任何重置不得删除输出镜像。
- [ ] 状态保存失败有明确错误和受影响恢复信息，不宣称已保存；为后续安全退出提供可验证的保存成功/失败结果。
- [ ] 应用 Interface 结合新进程或等价真实重新加载及临时目录，覆盖共享关联持久化、各阶段中断、无自动下载/协调、正式文件重新核验与人工恢复。
- [ ] 注入损坏/未知格式、保存失败和目录移动，验证原状态/镜像/未知文件保护及确认后空状态；正式界面可演示重开与主动恢复。
- [ ] 后续正常退出票接入“已停止（应用退出）”原因时，不破坏异常中断与既有完成/失败/取消结果的区别。
