# 19: 连续提交到跨目录共享有界并发队列

**What to build:** 用户连续提交多个单发行版本、单目标下载项，它们进入同一个共享有界并发队列并复用重复文件；每项绑定自己的目录并呈现进度，同根索引协调不与并发下载互相破坏。

**Blocked by:** 17 — 准备全部六目标的固定必需格式。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 后续提交可以与先前提交并发执行，下载请求分组仅用于汇总及后续取消，不形成整项串行屏障；并发有明确上限，由实现与验证决定，不固定为原型三槽。
- [ ] 同镜像根及官方相对路径的具体文件只创建/执行一个获取任务，多个下载请求分别关联；发行版本清单与官方附件也跨提交共享。
- [ ] 不同输出目录的同名文件不被误视为同一已满足文件；每项绑定提交时用户明确选定的目录，切换当前目录或候选选择不改绑已提交项。
- [ ] Rust 持有权威下载请求、文件任务及关联，前端从快照和进度展示；重新连接能恢复展示，不凭收到的零散通知推测已完成。
- [ ] 展示每项发行版本、目标、目录、文件满足情况与汇总进度，文件状态可解释；全局传输量只计唯一实际传输，不按需求引用重复累计。
- [ ] 某文件失败不停止其他独立任务，目录共享故障只影响依赖该目录的工作；其他可用目录继续。
- [ ] 同根索引协调串行、下载仍可并发，协调考虑同时追加的内容，旧结果不能覆盖新事实；任何未完成写入期间该根不可交付。
- [ ] 队列与索引状态分开呈现，不以某下载项结束、字节进度完成或全部文件任务成功替代镜像可交付判断。
- [ ] 应用 Interface 测试用受控网络任务证明后提交推进、并发上限、同根去重、跨根隔离、附件共享及全局计量，不绑定某个线程或唯一调度顺序。
- [ ] 临时目录与故障注入验证多根独立进度、同根串行协调及并发追加一致性；正式界面可演示多个下载项共同推进，不暗示多人共享。
