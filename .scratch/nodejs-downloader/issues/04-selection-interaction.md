# 搜索、多选与目标平台组合的交互模型

Type: prototype
Labels: wayfinder:prototype
Status: claimed
Blocked by: 02, 09, 10
Assignee: collin

本议题借助低保真原型与用户讨论选择行为，不制作正式应用界面。

## Question

在支持“搜索、多选发行版本、当前受支持 LTS 过滤、为选中版本应用一组目标平台和格式”的前提下，怎样的交互模型能让用户明确知道最终会下载哪些文件？

待明确搜索匹配与排序、筛选后保留选择的规则、全选当前结果与全选所有结果的区别、跨版本不可用组合的呈现，以及任务提交前的文件清单确认。不能让不可用组合静默生成失败下载，也不能将批量目标配置误当成每个发行版本都有这些文件。

待 [官方版本目录与当前受支持 LTS 的判定依据](02-release-catalog.md) 完成后，加载 `prototype` 与 `domain-modeling`，使用最便宜的可反应原型与用户讨论。不实现生产代码、不自行代替用户评价原型；任何可执行原型需另获确认。

## 已确认的系统与架构联动规则

用户确认以下规则，并授权更新[交互原型](../04-selection-interaction-prototype.html)。它们是本议题的部分决定，不代表搜索、多选、全选与最终清单交互已全部通过体验确认；本议题保持 `Status: claimed`。

- 系统仅考虑 macOS、Windows、Linux，架构仅考虑 x64、ARM64；系统与架构使用两个下拉框，选定后加入本批目标列表。
- 此处“支持”专指该发行版本的目标组合在官方清单中具有全部必需格式，不是 LTS 支持状态，也不等于已通过客户端安装验收。macOS/Linux 必须同时具备 `.tar.xz` 与 `.tar.gz`，Windows 必须具备 `.7z`；可选格式不能替代必需文件。
- 联动范围是全部已勾选发行版本，包括被搜索或 LTS 筛选隐藏但仍保留选择的版本；不得用当前可见结果或整个上游目录替代。
- 未选发行版本时允许浏览系统和架构，但“加入目标平台”置灰并提示先选择版本。
- 系统与架构下拉框始终正常显示、允许浏览所有范围内选项；不根据已选发行版本置灰选项，不附加支持数量或可用状态后缀。
- 当前系统与架构组合没有任何已选发行版本必需格式齐备时，仅将“加入目标平台”按钮置灰，不在选择区额外展示支持比例或缺项解释；不因某一个文件存在就允许加入。仅在清单成功取得后才能据此判定缺项；加载/解析失败沿用[分发变体支持范围](10-distribution-variants.md)的错误和主动重试规则，不冒充上游不存在文件。
- 部分支持时按钮可加入；整个界面不显示“支持 N/M 个版本”或可选格式覆盖比例。只有必需格式齐备的组合进入下载清单，不设置整批全部支持的门槛；已加入目标及下载前清单继续列明被排除的发行版本和缺项原因。
- 重复加入已在目标列表中的组合时按钮置灰，提示已加入。
- 改变已选发行版本后立即重算按钮、目标可用性和文件清单；当前浏览组合及已加入目标不自动切换或删除。失效的当前值仍显示，但加入被禁用；已加入目标在列表中保留并告警，缺项组合不进入清单，用户可以手动移除或调整版本选择。
- 原型界面与状态动作共用同一必需文件判定；直接触发原型动作也不能绕过未选版本、不支持和重复加入的限制。可选格式仅应用于必需文件齐备且实际提供该格式的组合。

### 原型体验情景

原型使用内存样例，不请求官方目录、不执行下载。故意设置的缺项不是官方版本事实：

- **整个系统不支持**：`v20.19.0` 演示样例没有 Windows 文件；系统和架构仍可选，只有加入按钮置灰。
- **架构缺少必需文件**：同一演示样例的 macOS ARM64 只有 `.tar.gz`；macOS 和 ARM64 仍可选，加入按钮置灰；改选齐备的 x64 后恢复可加入。
- **部分支持**：`v24.9.0` 演示样例缺少 Linux x64 的 `.tar.gz`，与齐备的 `v22.18.0` 一同选择时允许加入，不显示支持比例，仅齐备组合进入清单并列明被排除项。
- **改选后失去支持**：先为 `v26.1.0` 加入 Windows ARM64，再改选无 Windows 文件的演示样例；保留当前值和已有目标，明确告警，不再生成该组合的文件。
