# 17: 准备全部六目标的固定必需格式

**What to build:** 用户可以在约定下载器运行平台逐项准备 macOS、标准 Linux、Windows 的 x64/ARM64 内容；目标必需格式全部齐备且校验通过后才成为可用目标，镜像索引反映实际目标子集。

**Blocked by:** 16 — 完成首次 Windows x64 部分镜像准备。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 首次单请求链路扩展到六个目标组合；macOS/Linux 每项固定两种归档，Windows 每项固定 `.7z`，不以下载器自身系统过滤目标。
- [ ] 仅从真实官方清单确认必需文件；缺任一必需格式不允许提交，不生成不存在的下载候选，不提供可选格式、变体或自动补齐其他目标。
- [ ] 标准 Linux x64/ARM64 与 musl 明确隔离，musl 即使在官方清单中也不供选择、下载或收录。
- [ ] 每个归档分别通过 SHA-256 后才能成为正式文件；某归档成功而另一必需归档失败时，显示部分文件成功、目标尚不齐备，不让零散文件使新发行版本收录。
- [ ] 同一发行版本至少一个目标齐备且具备官方清单即可进入共享索引，不要求六目标全部成功；其他有效目标不因新增目标失败而丢失。
- [ ] 镜像索引保留官方表头、事实字段和语义版本降序，类别由实际校验通过内容按官方映射产生；不把类别列当作完整格式证明，不虚报未下载目标。
- [ ] 镜像根保留原始归档与清单相对结构，所有目标共用一个内容入口，不生成分平台入口或旧版专用发现内容。
- [ ] 界面按镜像根显示真实可用目标与未齐备项；文件齐备和请求结束不等于索引确认或可交付，无写入且索引一致才可交付有效子集。
- [ ] 通过应用 Interface 及临时目录验证六目标、双格式缺一、单目标齐备收录、多目标部分失败、类别映射及未下载目标不被宣称可用。
- [ ] 演示目标间切换及实际准备结果；自动化固定样例和实际下载结果都不能代替后续六目标真实客户端消费验收。
