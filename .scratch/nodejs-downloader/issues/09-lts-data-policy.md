# 生命周期数据失效与 LTS 筛选的边界策略

Type: grilling
Labels: wayfinder:grilling
Status: open
Blocked by: 02
Assignee: none

本议题决定如何在时间变化、来源缺失或缓存失效时兑现“只显示当前受支持 LTS”的用户承诺。

## Question

已知必须结合发行版本自身的 LTS 标记与官方发布线生命周期，第一版应如何处理官方日期的时区/结束日边界，以及生命周期来源不可用、过期或缺失时的筛选与提示？

依据 [官方版本目录与当前受支持 LTS 的判定依据](02-release-catalog.md)，与用户决定：

- 官方时间表只给日期时，采用哪个时区及区间边界；明确这是本应用约定，而非上游已保证的精确时刻。
- 索引和生命周期信息分别缓存多久、何时更新；跨日或跨 EOL 边界是否重新计算支持状态。
- 网络失败、时间表缺失或过期时，哪些结果可标为当前受支持，哪些仅能标为未知；不得静默将历史 LTS 当成仍受支持。
- 受支持发布线内的旧补丁如何展示；是否提示它不一定包含最新安全修复，不将仍受支持等同于推荐安装每个旧补丁。
- 本地时钟异常时能做哪些校验与提示，哪些不在第一版承诺内。

加载 `grilling` 与 `domain-modeling`，只解决产品策略，不实现判定函数或缓存。

## Comments

- 2026-10-13：由官方生命周期调研中的未决边界毕业为独立决策议题；用户的当前受支持 LTS 范围不变。
