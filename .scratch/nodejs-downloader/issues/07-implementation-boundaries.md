# 前端技术栈与下载引擎的职责边界

Type: grilling
Labels: wayfinder:grilling
Status: resolved
Blocked by: 03, 06
Assignee: collin

本议题选择足以支撑第一阶段业务承诺的实现路线，并为后续运行时保留合理职责边界，不提前脚手架、安装依赖或实现通用插件系统。

## Question

对于 macOS/Windows Tauri Node.js 镜像下载器，应该选择什么前端栈，以及怎样划分界面、上游版本目录、生命周期判定、下载引擎、本地镜像可用内容、索引生成和任务持久化的职责，才能满足第一版需求且保持可测试？

依据 [Tauri 跨平台下载与输出目录的技术约束](03-tauri-constraints.md) 和 [下载任务的恢复、失败与完成语义](06-download-lifecycle.md)，与用户决定：

- 前端框架与语言，插件驱动下载和 Rust 后端驱动下载的取舍。
- 应用级业务状态的唯一持有者、命令与事件契约，以及路径/URL 校验和权限边界。
- 上游下载候选与本地镜像可用内容如何分开表达，索引生成从什么可信输入取得事实；不能把上游索引直接当作已完成下载清单。
- 持久化范围与格式、网络和文件系统的可替换接口，以及适合本项目规模的模块深度。
- 哪些下载、写盘和校验能力可合理复用，哪些版本识别、支持周期、文件路径与镜像索引规则应留在 Node.js 领域边界；为以后 Python/uv 与 Go/voidint/g 留出替换位置，但不为未明确契约编写适配器或通用插件框架。
- 本地导出契约如何与未来 Nexus API 仓库选择和上传分离；本阶段不接入上传 API、不设计认证配置实现。
- macOS 与 Windows 的开发、验证和构建路线；不默认承诺在一台 macOS 机器上完成全部打包。

加载 `grilling`、`domain-modeling`；需要模块设计词汇时加载 `codebase-design`。只有确实满足难以反转、需要背景与真实权衡三个条件的决策才记录 ADR。不得因后续方向已经记录而自行选择跨运行时统一目录或 LTS 模型。

## Answer

- **技术路线与状态所有权：**前端采用 React + TypeScript；Tauri 2 / Rust 负责 Node.js 任务编排、下载和镜像文件操作，并持有权威任务状态及镜像可用性状态。前端只维护展示状态与未提交选择。命令用于请求操作和查询快照，Channel 用于高频有序进度，Event 用于轻量通知。
- **领域与权限：**只复用底层传输和文件操作能力；Node.js 版本目录、LTS、路径及索引规则留在 Node.js 领域，不提前建设 Python/Go 适配器或通用运行时插件框架。前端每次提交一个结构化发行版本与系统/架构目标，以及目录选择器选定的输出根目录；必需格式和官方辅助附件由 Node.js 领域规则确定，不由前端传入可选格式。Rust 从固定的 `https://nodejs.org/dist/` 来源构造 URL，并校验写入目标位于该根目录下的 `nodejs/`。第一版不接受任意 URL 或自定义镜像地址，Tauri 权限采用最小范围。
- **持久化：**在用户级应用数据目录保存带版本号的 JSON 状态，记录输出根目录、已提交的排队文件任务及其下载请求/提交分组关联，以及待处理、可重试、失败或中断状态。重启后不自动恢复网络任务；未完成任务标记为中断，手动重试从头开始，不保存完整完成历史。状态文件不作为内容可用性的证明；镜像可用性仍依据本地内容与官方校验结果。
- **模块与测试：**采用单个 Tauri/Rust crate，以内部模块划分任务编排、Node.js 领域规则、上游分发源、镜像文件操作和 JSON 状态存储。仅为网络和镜像文件操作保留窄接口及生产/测试 Adapter；领域规则使用固定数据测试，文件行为使用临时目录做集成测试。不为每个函数增加抽象，不拆分多个 crate，也不建设通用运行时框架。
- **桌面验证与构建：**macOS 与 Windows 分别在原生环境验证和打包；不承诺从 macOS 可靠地产出所有 Windows 安装包。CI 自动化留待实现阶段决定。

## Comments

- 2026-10-13 需求更新：用户将 Python/uv、Go/voidint/g、Nexus API 上传列为后续需求。当前只调整职责边界的决策问题，不提前实现这些功能，不锁定前端或后端技术路线，保持议题未解决。
- 2026-10-13 输入与队列同步：当前结构化输入为单个发行版本与一个系统/架构目标，格式由 Node.js 领域规则确定；JSON 状态需要表达共享文件任务及其各下载请求/提交分组关联。该更新不改变既定技术栈、权限边界和重启恢复政策。
