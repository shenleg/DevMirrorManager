# 下载任务的恢复、失败与完成语义

本议题确定下载行为、数据保护与镜像可用声明之间的边界，不将全部高级下载功能默认塞入第一版。

## Question

第一版需要怎样的任务状态与保障，才能在大文件、网络中断、重复选择、取消和应用重启后仍产生可信的镜像内容，并确保镜像索引只反映已完成且校验通过的下载？

基于 [nvm 双客户端与 Nexus 路径的兼容契约](01-mirror-protocol.md)、[Tauri 跨平台下载与输出目录的技术约束](03-tauri-constraints.md) 和 [部分镜像的索引、校验文件与可用性承诺](05-partial-mirror-policy.md)，与用户确定必要范围：

- 进度、取消、失败重试、暂停和重启恢复中，哪些必须在第一版具备。
- 并发边界、批次与文件任务关系，以及新增批次/重复任务的行为。
- 已有同名文件、校验失败、磁盘空间不足与目录不可写时，哪些动作可自动做，哪些必须确认；不能静默覆盖已存在数据。
- 临时文件、下载完成、校验通过、最终文件与元数据的完成条件，以及校验的信任依据；文件大小正常或网络请求完成不自动等于镜像可用。
- 镜像可用内容记录和索引在什么条件下更新，如何面对文件提交成功但索引更新失败、索引生成中断、重复任务或重启后的状态不一致；未完成和校验失败内容不得纳入可用声明。
- 用户选择的输出根目录及其 `nodejs/` 内容如何与任务绑定；目录改变、被移动或暂不可用时，任务与记录如何处理。
- 追加下载、重新校验或文件被外部修改后，怎样恢复镜像内容与索引的一致性；需要用户介入的边界仍待确定，不默认删除既有文件。

## Answer

用户于 2026-10-13 确认以下第一版任务生命周期、完整性与镜像交付语义。实现机制与 UI 细节留给后续议题；具体任务状态字段、并发数值和持久化格式不在本答案中锁定。

### 任务与批次

- 展示批次汇总进度和单文件任务进度；同一镜像根目录一次只处理一个批次，新提交批次排队。批次内允许有上限的并发，具体并发数由实现与测试调整。
- 同一文件的重复请求复用已有任务，不重复下载。
- 支持取消单个文件任务或整个批次，并允许用户手动重试失败项；不自动重试、不支持暂停或断点续传。
- 单个任务失败不阻断其他独立任务。任务全部结束后可形成部分成功的镜像；只有输出根目录不可用或无法安全更新索引等共享故障，才停止依赖该条件的操作。

### 下载、校验与已有文件

- 分发文件只有完成下载并通过官方 `SHASUMS256.txt` 中对应条目的 SHA-256 校验后，才能成为正式镜像文件并支撑镜像可用声明。
- 已有文件重新核验后匹配官方 SHA-256 时，可视为已满足；不匹配或无法安全核验时停止对应任务，不自动覆盖或删除原文件。
- 磁盘空间不足、目录不可写等故障停止受影响的任务并提示用户；未完成或校验失败的内容不得纳入镜像索引。

### 取消与临时文件

- 取消批次时停止排队任务并取消仍在下载的任务。只清理可确认归应用管理的未完成临时文件，保留已校验的正式文件。
- 若取消发生在正式文件提交或索引更新阶段，完成维持内容与索引一致所必需的步骤后再结束取消；取消不能留下与实际可用内容不一致的索引。
- 取消或失败任务的临时文件可以清理。异常退出后不自动启动网络任务；用户重新选择对应的已管理镜像并手动重试时，从头下载，并可清理可确认归应用管理的孤立临时文件。不得触碰正式文件或未知文件。

### 索引与可交付状态

- 先完成并校验正式分发文件，再根据重新核验后的镜像可用内容生成并更新完整索引。批次存在未完成写入时，镜像尚不可交付。
- 索引生成或更新失败时保留已校验文件和旧索引，不将镜像标为可交付；之后重新核验文件并协调索引。不得把未经索引确认的部分内容报告为已交付镜像。
- 内容与索引一致后，满足收录条件的部分结果仍可成为可交付镜像；一个任务失败不会撤销其他仍有效的内容。

### 输出目录与外部变更

- 任务绑定到用户明确选择的输出根目录及其下的 `nodejs/` 镜像根目录。路径不可用时停止并提示；目录移动后由用户重新指定并重新核验，不自动改绑、猜测路径或静默创建替代镜像。
- 每次更新索引前重新核验支撑可用声明的内容。若文件被外部删除或修改，索引如实撤下受影响的文件或平台声明并提示用户；保留磁盘文件，不自动修复、覆盖或删除。仍有效的其他内容继续保留。
