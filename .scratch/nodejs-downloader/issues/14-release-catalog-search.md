# 14: 在桌面应用中浏览与搜索官方发行版本

**What to build:** 用户能够启动正式桌面应用，浏览从官方来源取得的 Node.js 发行版本，按版本号前缀搜索并单选；目录加载、失败及刷新都有明确反馈。这是贯穿桌面界面、Rust 权威结果与测试的首个可运行切片，不是空脚手架。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 采用 React + TypeScript、Tauri 2 与单个 Rust crate，应用在约定 macOS/Windows 开发环境可运行；核实并锁定实际工具链与依赖，不宣称已通过安装包验收。
- [x] 上游版本目录来源固定为 Node.js 官方分发来源，校验必要元数据，不内置静态发行版本列表，不接受任意 URL 或自定义镜像地址。
- [x] 搜索去首尾空白和可选前导 `v`/`V`，按版本号文本前缀匹配；空查询可浏览候选，`22.1` 可匹配 `22.10`，结果按语义版本降序。
- [x] 发行版本单选，搜索使所选发行版本失配时清除该选择，不自动改选；后续目标选择与下载请求扩展不得改变这一语义。
- [x] 界面区分加载中、有效结果、空结果和获取/解析失败，错误说明原因并提供用户主动刷新，不把加载失败冒充没有发行版本。
- [x] 版本目录独立缓存 1 小时，过期后下次打开应用时刷新，支持手动刷新和 ETag 条件请求；缓存不是镜像可用内容证明。
- [x] Rust 提供经校验的候选与查询结果，前端维护未提交选择与展示；建立操作命令、权威快照及适当通知 Interface，重新连接可通过快照恢复展示。
- [x] 通过应用 Module 的公开 Interface 验证搜索、排序、单选及目录错误/刷新；固定数据覆盖异常元数据和条件响应，不以私有函数调用顺序作为断言。
- [x] 为官方网络访问建立生产/测试 Adapter 的窄内部 Seam，不为每个函数增加抽象，不建设通用运行时框架。
- [x] 演示真实桌面中的浏览、搜索、选择和刷新，记录实际验证环境；下载、镜像准备和正式安装包交付不在本票完成声明内。
