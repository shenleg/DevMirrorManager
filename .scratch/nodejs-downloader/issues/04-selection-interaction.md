# 版本搜索、单选与目标平台的下载交互

Type: prototype
Labels: wayfinder:prototype
Status: resolved
Blocked by: 02, 09, 10
Assignee: collin

本议题借助低保真原型与用户讨论单选和下载队列交互，不制作正式应用界面。

## Question

在支持版本号前缀搜索、单选发行版本、当前受支持 LTS 过滤和单一系统/架构目标的前提下，怎样让用户清楚知道一次提交会下载哪些文件，并能连续提交不同组合到共享队列？

确认搜索匹配与排序、筛选失配时的选择清除规则、固定必需文件与清单加载状态、目录选择、点击即提交，以及跨提交并发与去重。每次提交只对应一个发行版本和一个目标平台；不能让后续提交被前一提交整体阻塞。任务取消、异常反馈及镜像可交付状态的交互由[下载队列结果与异常反馈的交互原型](11-batch-feedback-prototype.md)继续决定。

本议题基于已完成的版本目录与生命周期决策，加载 `prototype` 与 `domain-modeling`，用低保真原型呈现交互规则。不实现正式应用，也不把自动化原型检查代替用户体验评价；当前原型修改已获授权。

## Answer

用户于 2026-10-13 明确将多选批量操作简化为单选流程，并确认格式、搜索筛选和直接提交的三个边界问题，授权更新[交互原型](../04-selection-interaction-prototype.html)与规划。本议题据此记录已确认的决策并设为 `resolved`。更新后的原型通过 7 个引导情景、17 项真实 DOM/状态检查，以及并发队列推进和 390px 窄视口检查，控制台无错误；这些检查验证原型行为，不代表用户已体验新 HTML，也不代表正式应用或客户端兼容验收通过。

### 搜索、发行版本与目标平台

- 搜索输入先去除首尾空白，再移除可选的前导 `v`，并按版本号文本前缀匹配；例如 `22.1` 可匹配 `22.10`。结果按语义版本降序排列。
- 同一时刻只选择一个发行版本。系统与架构分别由下拉框选择，每次提交只使用一个发行版本和一个系统/架构目标；系统范围为 macOS、Windows、Linux，架构范围为 x64、ARM64。
- 搜索结果、当前受支持 LTS 筛选或生命周期状态刷新后，若当前发行版本不再匹配，则清除发行版本选择；保留系统与架构，不自动选中其他版本。此类选择变化不影响已经提交的下载请求。
- 系统与架构下拉框始终可浏览范围内选项；不展示支持比例。只有成功取得并解析该发行版本的官方清单后，才能判定目标组合是否缺少必需文件。清单尚未就绪或加载/解析失败时禁用下载；失败时显示错误并提供用户主动重试，不能冒充上游缺少文件。

### 必需文件与直接提交

- 格式由目标平台的领域规则固定，界面不提供可选格式控件：macOS/Linux 必需 `.tar.xz` 与 `.tar.gz`，Windows 必需 `.7z`。原始 `SHASUMS256.txt` 和官方提供的签名附件随对应发行版本获取，不作为可选格式供用户勾选。
- 未选发行版本、清单未就绪或所选版本/目标平台缺少任一必需格式时，下载按钮禁用；下拉框仍可浏览。下载器不展示支持比例。
- 页面显示当前发行版本、目标平台、必需输出文件和输出目录。若尚未选择输出根目录，点击下载先打开目录选择器；用户取消则不提交。目录已确定且组合有效时，点击下载直接加入共享队列，不弹出下载确认对话框。
- 直接下载提交不改变既有的数据安全边界：同路径文件冲突仍须停止并提示用户，不得静默覆盖或删除。取消下载确认步骤不授权新增正式文件的重置或替换功能。

### 下载队列

- 每次下载提交对应一个发行版本和一个目标平台，并以关联文件任务呈现该提交的汇总与取消操作。多个提交进入共享的、有上限并发的下载队列，后续提交可与先前提交并发执行；提交分组不构成串行屏障。
- 同一具体文件在不同提交中只需获取一次，任务可由多个提交共享；发行版本级的校验清单与官方签名附件同样跨提交复用。取消操作、单文件取消入口及异常反馈已由[下载队列结果与异常反馈的交互原型](11-batch-feedback-prototype.md)的 `## Answer` 确定；此处不重复其详细规则。

### 原型体验情景

原型使用内存样例，不请求官方目录、不执行下载。故意设置的缺项不是官方版本事实；下列引导场景已做原型行为检查，但不代表用户已体验新 HTML 或体验结论已通过：

- **单选与直接下载**：改选另一个发行版本会替换原单选；Windows 只提交必需 `.7z` 和约定附件，不提交 ZIP；确认首次输出目录后直接入队。
- **搜索前缀与排序**：`  V24  ` 匹配 `v24.10.0` 和 `v24.9.0` 且按数字版本降序；搜索 `22.1` 匹配 `v22.18.0`，原单选因不再匹配而清除。`22.1` 也可匹配 `22.10` 是文本前缀规则，现有样例不含 `v22.10.x`。
- **筛选不改队列**：提交非 LTS 的 `v26.1.0` 后开启 LTS 筛选，清除当前单选，但保留系统/架构和已提交队列；未知支持状态、无 LTS 标记及 EOL 样例不进入结果。
- **系统与架构缺项**：`v20.19.0` 演示样例没有 Windows 文件，macOS ARM64 仅有 `.tar.gz`，下载均被禁用；系统/架构始终可浏览，改选齐备的 macOS x64 后恢复可下载。
- **后续提交参与并发**：先后提交 `v24.9.0` Windows x64 与 ARM64，两个分发文件可与共享清单同时推进；重复提交复用文件任务，不重复创建。
- **取消目录不提交**：无目录时点击下载会打开模拟目录选择器，取消按钮或 Escape 均不新增请求与文件任务，保留版本和目标。
- **清单未知不是不支持**：清单加载中/失败时禁用下载，不判定为目标缺文件；主动重试后恢复可下载。

原型不访问真实目录，不演示已有文件冲突、索引生成、共享任务取消或生命周期数据刷新；这些行为不能由上述检查宣称已验收。演示使用 3 个并发文件槽位，仅为了观察状态，不锁定正式并发上限。
