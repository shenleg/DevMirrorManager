# 第一版验收边界与开发规格的充分性

Type: grilling
Labels: wayfinder:grilling
Status: resolved
Blocked by: 04, 05, 06, 07, 11, 12
Assignee: collin

本议题确认第一阶段路线何时足以交给开发，验证用户必须需求而不把后续运行时、Nexus API 上传和生产发布混入第一版验收。

## Question

在选择交互、部分镜像内容契约、下载生命周期与实现边界明确后，第一版的验收必须覆盖哪些场景，才能证明 Node.js 下载、当前受支持 LTS/目标平台筛选、目录选择和内容驱动镜像索引均兑现了用户要求？哪些决定仍不足以写成可执行开发规格？

结合 [版本搜索、单选与目标平台的下载交互](04-selection-interaction.md)、[部分镜像的索引、校验文件与可用性承诺](05-partial-mirror-policy.md)、[下载任务的恢复、失败与完成语义](06-download-lifecycle.md) 和 [前端技术栈与下载引擎的职责边界](07-implementation-boundaries.md)，与用户确认：

- 搜索输入首尾空白处理、可选前导 `v` 去除、版本号文本前缀匹配（如 `22.1` 匹配 `22.10`）和语义版本降序；单选发行版本及当前受支持 LTS 的时间边界、未知状态处理。搜索/LTS 状态变化导致当前版本不再匹配时应清除选择、保留系统/架构且不自动选中其他版本；已提交请求不受影响。
- 单个发行版本与单个系统/架构目标的组合、由目标平台固定决定的必需格式（macOS/Linux `.tar.xz` 与 `.tar.gz`，Windows `.7z`）、官方校验清单及签名附件；界面没有可选格式控件。缺少必需格式只能由成功清单判定，清单未就绪或失败时禁用下载并显示错误和主动重试。
- 用户选择的非仓库输出目录，`nodejs/` 下的原始相对路径，以及目录改变、不可写和已有内容保护。页面显示版本、目标、固定输出文件和目录；有效选择点击即提交且不弹下载确认；未选目录时先打开目录选择器，取消不提交。
- 跨提交共享的有界并发下载队列、按提交汇总/取消但不形成串行屏障、同文件及校验/签名附件跨提交去重、部分失败和手动重试。
- 镜像索引与实际已完成且校验通过的内容一致；未下载、未完成、校验失败的内容不能被宣称可用。只下载部分平台时，如何证明发现与安装行为符合限定的兼容承诺。
- 首次下载、追加下载、取消、索引生成失败和重启之后，哪些内容与索引一致性场景必须覆盖；同一镜像根的索引更新须协调串行，存在未完成写入时不可交付；不仅检查下载列表显示成功。
- 两个 nvm 客户端各自必须成功的使用场景、固定验收客户端版本/环境、压缩格式和别名发现行为，以及 Nexus 路径映射的必要前提。旧版 Windows 的外部 npm 获取和新版其他外围联网不能被默认为已实现完全离线；源码请求契约不等于真实客户端验收已通过。
- 如何验证镜像消费契约而不依赖尚未实现的 Nexus API 上传；第一版不以 Python/uv、Go/voidint/g 或 API 仓库选择为验收条件。
- macOS 与 Windows 上分别需要怎样的自动化与真实桌面验证。
- 是否仍有阻止第一阶段开发的决定；若有，仅将已可精确描述的问题建立新议题，其余保留为本阶段地图中的雾区，不把后续阶段需求加回雾区。

加载 `grilling` 与 `domain-modeling`。本议题的答案记录验收与交接决策，不实际执行下载、安装、上传或发布。

## Answer

用户于 2026-10-13 分两轮确认全部推荐，确定以下第一版验收要求及规格交接边界。本答案记录未来开发和验收的通过标准，不表示已经运行正式应用、下载 Node.js、安装客户端或通过任何真实兼容验收。

### 1. 完成状态与证据门槛

- 分开记录规划完成、开发完成和验收通过；源码调研、HTML 原型检查、开发环境运行或下载列表显示成功，不得替代正式应用的验收证据。
- 第一版交付必须具备领域规则及故障场景的自动化测试、macOS/Windows 实际安装包的原生验证，以及下述固定 nvm 客户端的真实镜像消费验证。
- 缺少环境、未执行或未通过的项目明确记为待验证或失败，不能宣布全部验收通过。允许先完成规划，不以现在搭建环境或执行安装为本地图决策的前提。
- 每项验收关联既有决策和预期结果，记录实际环境、步骤、结果及证据；具体测试框架、机器分配和实施安排交执行阶段确定。

### 2. 自动化与正式界面必须覆盖的业务规则

- 依据 [版本搜索、单选与目标平台的下载交互](04-selection-interaction.md)，验证查询首尾空白、可选前导 `v`、文本前缀匹配和语义版本降序；单选发行版本及一个目标平台；搜索或 LTS 状态变化导致失配时清除发行版本、保留目标、不自动改选、不影响已提交请求。
- 依据 [生命周期数据失效与 LTS 筛选的边界策略](09-lts-data-policy.md)，验证 UTC 生命周期边界、发行版本 LTS 标记与发布线支持状态分离、缓存与重判、未知状态及旧补丁提示；不把客户端 LTS 别名当作当前受支持 LTS 的证据。
- 依据 [同一目标平台的分发变体支持范围](10-distribution-variants.md)，验证范围内系统/架构和标准 Linux 变体；不存在可选格式控件、支持比例或 musl 选择。macOS/Linux 固定两种归档，Windows 固定 `.7z`。
- 清单未就绪、获取或解析失败时禁用下载并显示错误与主动重试；只有成功清单才能证明必需文件缺失，不能把清单失败显示为目标平台不支持。
- 选择仓库外输出根目录，验证内容位于其下 `nodejs/` 且保留官方原始路径；未选目录时先打开选择器、取消不提交；有效选择直接入队，不增加下载确认弹窗。
- 下载请求跨提交共享有界并发，不形成提交串行屏障；分发文件、发行版本清单和签名附件去重，按提交汇总并取消，遵循 [下载队列结果与异常反馈的交互原型](11-batch-feedback-prototype.md) 已确认的入口、共享文件解释、部分结果及异常反馈。并发数字不是原型的固定三槽，具体上限由实现与测试调整。
- 前端展示不能冒充下载引擎的权威状态；采用 [前端技术栈与下载引擎的职责边界](07-implementation-boundaries.md) 已确定的结构化输入、Rust 领域规则、路径边界与最小权限，不在验收议题重选技术栈。

### 3. 数据保护与异常一致性是硬门槛

- 取消一个下载请求，不停止其他请求仍需的共享文件；无其他需求的未完成文件可取消，已校验正式文件保留。安全提交或索引阶段按既定取消契约处理，协调失败不能冒充取消完成且镜像可交付。
- 覆盖首次下载、追加下载、网络中断、SHA-256 失败、清单失败、部分失败、手动重试及异常退出/重启；无自动重试、无断点续传，重启不自动联网。未完成或校验失败内容不能成为可用内容。
- 覆盖已有管理镜像的有效文件复用、同路径冲突/损坏/无法安全核验、非管理目录、目录不可写/不可用、空间不足和目录变更；不静默覆盖、删除、接管未知文件或改绑到替代路径。正式文件重置/替换不作为新增能力。
- 官方清单原始字节保留；归档通过官方 SHA-256 校验后才能成为正式文件。官方签名附件获取失败单独告警，不阻止其他条件满足的内容收录；不执行或声称通过 PGP 验证。
- 检查索引声明对应实际齐备且校验通过的目标平台，未下载目标不得虚报；每次索引更新前重新核验支撑声明的内容，外部修改/删除导致撤下受影响声明，仍有效的其他平台继续保留。
- 验证同根索引协调串行、下载仍可并发、内容先于完整索引替换；索引生成/写入失败保留正式文件和旧索引，明确尚不可交付，并支持手动重新核验协调。存在任何未完成写入时该镜像根不可交付；全部相关写入结束且索引一致后，有效子集可交付，不要求所有下载请求成功。
- 上述故障优先用小型受控文件和故障注入自动化覆盖，不必每个异常都下载真实 Node.js 大文件；这些测试不能替代下一节的真实客户端链路。

### 4. 真实客户端最低验收矩阵

沿用 [部分镜像的索引、校验文件与可用性承诺](05-partial-mirror-policy.md) 的固定客户端版本，不扩大到旧版客户端、源码构建或完全离线安装。

| 客户端 | 消费环境 | 必须真实消费的格式 |
| --- | --- | --- |
| `nvm-sh v0.40.8` | macOS x64 | 分别验证 `.tar.xz` 与 `.tar.gz` |
| `nvm-sh v0.40.8` | macOS ARM64 | 分别验证 `.tar.xz` 与 `.tar.gz` |
| `nvm-sh v0.40.8` | 标准 Linux x64，非 musl | 分别验证 `.tar.xz` 与 `.tar.gz` |
| `nvm-sh v0.40.8` | 标准 Linux ARM64，非 musl | 分别验证 `.tar.xz` 与 `.tar.gz` |
| `nvm-windows v2.0.1` | Windows x64 | `.7z` |
| `nvm-windows v2.0.1` | Windows ARM64 | `.7z` |

- 每个组合验证镜像版本发现、精确发行版本的二进制安装，以及安装后实际执行 `node --version` 与所选发行版本一致；选择官方实际具备所需必需文件的发行版本。
- nvm-sh 两种格式通过客户端工具环境控制，不修改客户端源码；保留请求日志证明实际请求并使用了相应归档，不把协议模拟或仅静态路径检查算作真实消费。
- 允许虚拟机，仍需实际安装和运行对应架构的 Node.js。具体 Linux 发行版、系统版本、工具环境和官方测试发行版本由执行者在既定契约内固定并记录，不承诺穷举所有历史发行版本或发行版。
- Windows ARM64 是镜像客户端消费环境，不新增 Windows ARM64 下载器安装包；Linux 消费验证不新增 Linux 桌面应用。缺少任一约定消费环境时记为待验证，不宣称全矩阵通过。

### 5. 部分镜像的发现、别名与预期限制

- 使用独立或已明确处理缓存的客户端环境，发现结果以测试镜像子集为依据，不凭空包含未收录的上游发行版本。记录缓存前提，不要求客户端缓存立即刷新。
- 本机必需文件齐备时，精确版本安装成功；索引、所需清单和分发文件请求来自测试镜像。客户端支持的 latest、LTS、主版本等选择按共享镜像子集解析，所选目标适用于本机且文件齐备时应能安装。
- 为两个客户端覆盖部分平台镜像与合并索引的边界：可以发现只有其他平台文件的发行版本；别名可能选中本机无法安装的发行版本，不要求自动寻找本机可安装的次新版本。镜像最新不等于官方最新，客户端 LTS 不等于应用的当前受支持 LTS。
- 缺少本机文件时，不以客户端回源、切换其他镜像或源码构建后的成功，作为本镜像安装通过；记录实际解析结果、请求和失败/回退行为，不把已接受的发现限制误报为下载器必须补齐所有平台。
- 证据包括客户端版本、系统/架构、格式环境、操作、解析结果、安装及运行结果和服务请求日志；允许客户端必要的外围联网，但不能掩盖镜像内容缺失，也不能据此宣称完全离线兼容。

### 6. 验收服务与桌面交付边界

- 使用可控的匿名 HTTPS 静态服务暴露生成的 `nodejs/` 实际内容，镜像 URL 指向该内容根；不依赖目录 HTML、软链接、旧版专用发现文件或交互认证。纯 HTTP 可以作为内部测试手段，不能替代既定匿名 HTTPS 的最终客户端消费验收。
- 第一版不以 Nexus 上传 API、生产 Nexus 联调或公开部署为前提；未来上传仍以 `nodejs/` 内相对路径为准，并遵守内容先于索引的交付约束。验收执行所需服务与客户端设置不代表应用新增配置 nvm、部署服务或上传能力。
- 原生桌面验收严格沿用 [第一版桌面交付的安装、签名与更新要求](12-desktop-release-requirements.md)：macOS Apple Silicon/Intel 分架构 DMG、Windows x64 当前用户 NSIS，覆盖 macOS 13、Windows 10 22H2 / Windows 11 支持基线。
- 用实际安装包验证安装、首次运行及界面，记录安全提示，不绕过系统/组织保护；覆盖 Windows WebView2 已有、缺少及依赖安装失败，手动升级、数据保留、卸载保留镜像，以及不兼容/损坏状态保护与经确认启用新空状态。缺少环境记为待验证，不以开发模式代替安装包，也不要求穷举全部系统补丁。
- Python/uv、Go/voidint/g、Nexus API 仓库选择与上传、生产发布不属于本阶段验收条件。

### 7. 规格充分性与剩余决策

- 本议题的验收范围、最低矩阵及证据门槛已明确，可以解决本议题；这不等于地图目的地已经到达或验收已经通过。
- 核对现行决定发现正常关闭窗口/主动退出时处理进行中工作的语义未明确。用户同意单独建立 [存在进行中任务时的关闭与退出行为](13-close-and-exit-behavior.md)；本轮不替用户选择后台继续、立即中断或提示等待，不解决第二个议题。
- 该行为决定前，不能宣布完整开发规格已无未决事项；该问题单独成票，不重复放进雾区。后续已由[存在进行中任务时的关闭与退出行为](13-close-and-exit-behavior.md)解决，并以其 `## Answer` 补充正常关闭、退出、安全阶段、失败退出及重新打开的验收要求；具体退出决策只保存在该议题，不在此重复。
- 已确定的并发数字选择、crate/依赖版本、状态字段、测试框架及机器安排属于实现/执行细节，不作为新增产品阻塞。剩余决策解决后，才可按地图目的地收口并整理开发规格；本轮没有生成完整 `spec.md` 或授权正式应用实现。
