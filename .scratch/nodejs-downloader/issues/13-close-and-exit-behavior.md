# 存在进行中任务时的关闭与退出行为

Type: grilling
Labels: wayfinder:grilling
Status: resolved
Blocked by: 06, 08, 11, 12
Assignee: collin

本议题决定第一版下载器在正常关闭窗口或主动退出时如何处理进行中工作，补齐开发规格的用户可见行为；不实现后台服务、托盘或退出流程。

## Question

当下载器仍有排队、下载、校验、正式文件提交或索引协调工作时，普通关闭窗口与主动退出分别应如何处理，才能使用户预期、数据保护和重启后的手动恢复一致？

现行契约已确定异常退出后不自动联网、手动重试从头下载、安全提交及索引阶段取消须完成必要的一致性步骤，但尚未决定普通关闭窗口是否退出应用、是否后台继续及是否需要提示。不得把异常退出策略直接当作正常退出策略，也不得因后台能力在技术上可实现而将其视为已批准。

结合 [下载任务的恢复、失败与完成语义](06-download-lifecycle.md)、[第一版验收边界与开发规格的充分性](08-acceptance-boundaries.md)、[下载队列结果与异常反馈的交互原型](11-batch-feedback-prototype.md) 和 [第一版桌面交付的安装、签名与更新要求](12-desktop-release-requirements.md)，与用户确认：

- macOS 与 Windows 的关闭窗口、关闭最后一个窗口及主动退出是否具有相同语义；如不同，如何使窗口恢复入口和任务状态明确。普通窗口关闭不应被未经讨论地解释为异常退出。
- 存在排队或进行中工作时，选择后台继续、立即退出并中断，还是提示后安全结束；是否允许撤销退出，以及提示应说明哪些受影响工作。
- 正常退出时如何处理不同输出目录的任务、持久化状态和共享文件；不新增界面上的“取消全部队列”能力，不因退出删除正式文件或未知内容。
- 正式文件提交、索引协调等安全阶段遇到退出请求时，应等待哪些步骤，显示什么反馈；若协调失败、目录不可用或等待无法正常结束，用户有哪些安全选择，何时可以退出，如何保持旧文件、旧索引和不可交付状态。
- 重新打开应用后怎样展示正常退出留下的未完成工作；沿用不自动联网、无断点续传和手动从头重试的既定约束，除非用户明确重新讨论这些承诺。
- 正常空闲退出、进行中退出、撤销退出、安全阶段退出和退出后重新打开，应纳入哪些自动化及原生桌面验收场景；不在本轮执行这些验证。

## Answer

用户于 2026-10-13 逐轮确认 Q1–Q8 全部推荐，并在最终汇总后授权更新文档、提交和推送。以下规则补齐第一版正常关闭与退出的产品决策；本轮不实现退出流程，不运行正式应用或执行验收。

### 1. 关闭窗口与主动退出

- macOS 与 Windows 统一语义：关闭主窗口（包括 macOS 红色关闭按钮及关闭最后一个窗口）、菜单退出和退出快捷键，都进入同一个退出流程。第一版不采用关窗后后台下载，不新增托盘、后台服务或窗口恢复入口。
- 最小化窗口不属于退出，任务继续运行。
- 没有排队或进行中工作、也没有待处理的镜像一致性问题时，直接退出。普通失败、取消或官方签名附件告警本身不触发索引未确认的退出警告。
- 第一版不提供“全部下载完成后自动退出”。

### 2. 有任务时的退出提示

- 存在排队、下载、校验、正式文件提交或索引协调工作时，先提示退出影响所有输出目录的未完成工作，提供“继续下载”和“停止并退出”。
- 提示说明：已校验正式文件保留；重新打开不会自动续传，未完成文件需要手动从头重试。
- 提示显示期间任务继续运行；选择“继续下载”或关闭提示，都仅放弃本次退出，不改变任务与下载队列。
- “停止并退出”是退出流程的全局停止语义，不在下载页面新增“取消全部队列”按钮，不改变平时取消某项下载不能停止其他下载所需文件的既定规则。

### 3. 确认停止后的安全收尾

- 确认“停止并退出”后停止派发排队任务，阻止新提交与重试，中断可以安全中断的下载和校验；不为退出而把剩余文件下载完。
- 跨下载项复用的文件按唯一文件任务处理，不因多个需求引用重复停止或重复收尾；退出涉及应用内所有目录的进行中工作，而非只停止当前所选目录。
- 已进入正式文件提交或索引替换的工作，完成必要的安全步骤；对已提交的有效内容完成必要的索引一致性处理。不在提交或替换中途截断写入，不因退出删除正式文件或未知内容。临时文件边界沿用[下载任务的恢复、失败与完成语义](06-download-lifecycle.md)，不新增清理权限。
- 显示“正在停止并安全退出”，说明正在等待的文件、目录与步骤，不用无原因的等待状态掩盖进度。
- 确认停止后不提供恢复原队列的“撤销退出”。等待或故障导致用户返回应用时，仅放弃本次退出意图；已停止工作不自动恢复，已经开始的安全收尾仍须完成，未结束前继续限制会与其冲突的操作。
- 重复关闭窗口或请求退出复用当前退出流程，不启动第二套收尾，不跳过必要等待。

### 4. 多目录、协调失败与等待边界

- 按镜像根目录列出收尾结果。一个目录失败不妨碍其他目录完成安全收尾，但整体退出必须满足各目录的安全条件及应用任务状态保存要求。
- 正式文件已经保存但索引协调失败时，保留已校验正式文件和旧索引，明确受影响目录“索引未确认、尚不可交付”，不得将下载成功或收尾失败报告为镜像交付成功。
- 不要求用户修好不可用目录或索引才能退出。所有相关写入结束，且成功保存“索引未确认、需要重新核验与协调”的未完成状态后，提供“返回应用处理”和“保留未完成状态并退出”；后者须用户明确选择，不静默退出。
- 如果连任务状态都无法保存，或相关写入仍未结束，不报告安全退出成功。显示失败或等待原因并允许返回应用，不提供绕过安全步骤的“强制退出”按钮。
- 等待较久时说明当前步骤与受影响路径，不以固定超时强杀进程。具体提示阈值由实现阶段确定，不属于本议题新增产品阻塞。
- 用户通过操作系统强制结束、系统关机中断或其他异常造成流程未完成，按异常退出处理；不承诺应用能阻止这些操作，也不把它们计作正常安全退出。

### 5. 空闲但镜像尚不可交付

- 没有运行中的任务，但存在待处理的镜像索引一致性问题时，退出仍须提醒“以下镜像索引未确认，尚不可交付”，列出受影响目录，提供“返回应用”和“仍然退出”。
- 不要求先修复才能退出，但仍须满足无进行中写入、未完成状态保存成功及用户明确确认的要求。普通文件失败、取消或签名附件告警不等同于索引一致性问题。

### 6. 重新打开后的状态与手动恢复

- 正常退出停止的未完成工作显示“已停止（应用退出）”；异常退出留下的未完成工作显示“已中断”。已完成、失败和此前已取消的结果保留，不一律改成已停止。
- 保留下载项、绑定目录及文件关联；重新打开不自动恢复下载，也不自动执行未完成的索引协调。
- 用户重新选择对应的已管理镜像后，主动重试未完成文件，从头下载，不支持断点续传；已有正式文件只有重新核验符合官方校验依据后才能复用。
- 索引未确认的目录继续显示“尚不可交付”，由用户主动重新核验与协调。历史成功记录与任务状态文件都不能直接证明当前磁盘内容仍有效。
- 不自动猜测路径、改绑到新目录或创建替代镜像；目录与文件保护继续遵循已有生命周期契约。本议题不改变上游版本目录刷新等既定业务需求。

### 7. 验收与规格收口

以下要求补充[第一版验收边界与开发规格的充分性](08-acceptance-boundaries.md)，同时纳入自动化测试与 macOS/Windows 实际安装包的原生验证；具体故障注入方式与测试安排由执行阶段决定。

- 空闲关闭、主窗口关闭（包括最后一个窗口）、菜单/快捷键退出的一致性，以及最小化不停止任务。
- 退出提示期间任务继续，放弃退出或关闭提示不改变队列；确认停止后阻止新工作，不自动恢复已停止任务。
- 排队、下载、校验、正式文件提交与索引更新各阶段退出，覆盖跨下载项共享文件和多个输出目录。
- 索引协调失败、目录失联、任务状态保存失败、长时间等待、返回应用与重复退出；不得误报安全退出或镜像可交付，不超时强杀。
- 正常退出后重新打开、收尾中被系统强制结束后重新打开，以及手动从头重试、正式文件重新核验和未知文件保护。
- 所有当前决策议题已解决，关闭与退出不再是规格未决事项。后续可据决策记录整理完整开发规格；本轮未生成 `spec.md`，没有正式应用、安装包或客户端验收证据，不将决策齐备等同于开发完成或验收通过。
