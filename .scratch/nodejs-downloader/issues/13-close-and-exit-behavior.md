# 存在进行中任务时的关闭与退出行为

Type: grilling
Labels: wayfinder:grilling
Status: open
Blocked by: 06, 08, 11, 12
Assignee: none

本议题决定第一版下载器在正常关闭窗口或主动退出时如何处理进行中工作，补齐开发规格的用户可见行为；不实现后台服务、托盘或退出流程。

## Question

当下载器仍有排队、下载、校验、正式文件提交或索引协调工作时，普通关闭窗口与主动退出分别应如何处理，才能使用户预期、数据保护和重启后的手动恢复一致？

现行契约已确定异常退出后不自动联网、手动重试从头下载、安全提交及索引阶段取消须完成必要的一致性步骤，但尚未决定普通关闭窗口是否退出应用、是否后台继续及是否需要提示。不得把异常退出策略直接当作正常退出策略，也不得因后台能力在技术上可实现而将其视为已批准。

结合 [下载任务的恢复、失败与完成语义](06-download-lifecycle.md)、[第一版验收边界与开发规格的充分性](08-acceptance-boundaries.md)、[下载队列结果与异常反馈的交互原型](11-batch-feedback-prototype.md) 和 [第一版桌面交付的安装、签名与更新要求](12-desktop-release-requirements.md)，与用户确认：

- macOS 与 Windows 的关闭窗口、关闭最后一个窗口及主动退出是否具有相同语义；如不同，如何使窗口恢复入口和任务状态明确。普通窗口关闭不应被未经讨论地解释为异常退出。
- 存在排队或进行中工作时，选择后台继续、立即退出并中断，还是提示后安全结束；是否允许撤销退出，以及提示应说明哪些受影响工作。
- 正常退出时如何处理不同输出目录的任务、持久化状态和共享文件；不新增界面上的“取消全部队列”能力，不因退出删除正式文件或未知内容。
- 正式文件提交、索引协调等安全阶段遇到退出请求时，应等待哪些步骤，显示什么反馈；若协调失败、目录不可用或等待无法正常结束，用户有哪些安全选择，何时可以退出，如何保持旧文件、旧索引和不可交付状态。
- 重新打开应用后怎样展示正常退出留下的未完成工作；沿用不自动联网、无断点续传和手动从头重试的既定约束，除非用户明确重新讨论这些承诺。
- 正常空闲退出、进行中退出、撤销退出、安全阶段退出和退出后重新打开，应纳入哪些自动化及原生桌面验收场景；不在本轮执行这些验证。
