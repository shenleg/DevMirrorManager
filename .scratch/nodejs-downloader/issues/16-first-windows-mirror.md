# 16: 完成首次 Windows x64 部分镜像准备

**What to build:** 用户选定具备必需文件的 Windows x64 发行版本，选择输出目录并直接提交一项下载；应用展示进度，保存校验通过的归档、原始清单及官方附件，生成反映实际内容的镜像索引，明确何时可交付。这是单请求的首次完整链路，安全写盘不能推迟到后续票。

**Blocked by:** 15 — 按目标平台预览真实必需文件。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 页面显示发行版本、目标、必需输出及输出目录；未选择输出根目录时点击有效下载先打开原生目录选择器，取消不创建请求或文件任务且保留选择，确定后直接提交，不增加下载确认弹窗。
- [ ] 一个下载请求绑定一个发行版本、Windows x64 目标及明确目录；Rust 从固定官方来源构造文件请求，不接受任意 URL，未提交选择变化不改绑已提交请求。
- [ ] 新镜像仅在镜像根不存在或为空时建立，创建基本管理记录；拒绝自动接管非管理非空镜像，已有路径冲突停止并提示，禁止静默覆盖或删除。
- [ ] 官方原始文件名和相对结构保留，不解压、改名或执行归档；临时内容及管理记录在镜像根外，写盘校验输出范围并防止越界，不把插件 scope 当作后端授权。
- [ ] `.7z` 下载完整且匹配原始官方清单中的 SHA-256 后才提交为正式文件；部分内容、hash 失败或请求成功本身不能支撑可用声明。
- [ ] `SHASUMS256.txt` 原始字节保存；获取并原样保存官方提供的签名附件，附件获取失败单独告警，不阻止其他条件满足的内容收录，不显示 PGP 验证通过。
- [ ] 界面通过 Rust 权威快照/进度显示下载项与文件的排队、传输、校验、正式提交及结果；网络或写入失败有原因，不自动重试，不把错误显示为可交付。
- [ ] 在用户级应用数据建立带版本的基本状态和目录管理身份，保留恢复所需关联；管理记录不能直接证明磁盘可用，不建设完整历史系统。
- [ ] 正式归档和清单先于完整镜像索引提交；至少该目标必需内容齐备才收录发行版本，保留官方字段与真实类别，不复制上游全量索引或虚报其他平台。
- [ ] 同根仍有写入、索引生成/保存失败或一致性未确认时不可交付；失败保留已校验正式文件和已有索引，不以文件完成冒充镜像成功。
- [ ] 用受控小文件、网络/镜像文件 Adapter 和实际临时目录，通过应用 Interface 证明完整链路、路径保护、未知目录拒绝、冲突无覆盖、hash 失败隔离、附件告警及索引发布顺序。
- [ ] 在正式应用演示单项 Windows x64 镜像准备，记录验证环境；本票不宣称已具备全目标、共享队列、完整恢复/退出或真实 nvm 兼容验收。
