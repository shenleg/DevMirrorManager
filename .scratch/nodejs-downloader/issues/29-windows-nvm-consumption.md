# 29: 验证 Windows 上 nvm-windows 的真实镜像消费

**What to build:** 通过固定 nvm-windows 真实验证应用准备的 Windows x64/ARM64 `.7z` 部分镜像可以被发现、精确安装并运行，且别名和缺本机文件行为符合共享索引限制；不新增 Windows ARM64 下载器安装包。

**Blocked by:** 22 — 安全追加、重新核验与恢复镜像索引一致性。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 固定 `nvm-windows v2.0.1`，在 Windows x64 与 ARM64 环境实际安装并运行对应架构 Node.js；记录客户端、系统/架构与所需工具，不用旧版客户端代替。
- [ ] 两架构都必须实际请求并消费 `.7z`，原始官方清单用于校验；ZIP、客户端模拟或仅文件存在性不能替代真实标准在线安装路径。
- [ ] 选择官方清单证实文件齐备的发行版本，由正式应用生成内容，通过受控匿名 HTTPS 暴露实际内容根，不依赖目录 HTML、软链接、交互认证或旧版发现文件。
- [ ] 独立或明确处理缓存的客户端发现列表来自镜像子集；索引、所需清单与归档来自测试镜像，精确安装后执行 `node --version` 与所选发行版本一致。
- [ ] 验证客户端支持的 latest、LTS、主版本选择按共享子集解析，本机目标齐备时可安装；不声称镜像最新等于官方最新或客户端 LTS 等于应用当前受支持 LTS。
- [ ] 部分平台镜像中覆盖只有其他目标齐备的发行版本可被发现、别名可能选中本机不可安装目标的行为，不要求自动次新回退或下载器自动补齐。
- [ ] 缺文件时记录实际请求、失败或镜像切换行为；回源或切换另一镜像成功不得计为测试镜像通过，外围联网不能掩盖内容缺失，不宣传完全离线。
- [ ] 允许虚拟机但必须真实运行目标架构 Node.js；缺 ARM64 环境记待验证，不将 x64 成功或文件路径相似当作 ARM64 通过。
- [ ] 记录固定客户端版本、两个消费架构、测试发行版本/镜像子集、缓存前提、系统/工具、操作、解析、安装/运行及 HTTPS 请求日志。
- [ ] 未执行项目、缺环境和失败明确列出；如出现协议差异提交复现，不通过改客户端、改用 ZIP 或扩大兼容范围掩盖。
- [ ] 本票验证消费者而非下载器安装架构，不新增 ARM64 下载器安装包，不要求完成 Nexus 上传，也不能替代 Windows x64 原生安装包验收。
- [ ] 环境安装、客户端配置、外部内容暴露及红线操作按项目授权要求执行；生成本票不预授权公开部署、用户数据删除或凭证修改。
