# 22: 安全追加、重新核验与恢复镜像索引一致性

**What to build:** 用户可以继续准备已管理的镜像，复用重新核验有效的正式文件，并在外部修改或索引失败后主动恢复真实可用声明；应用保护已有内容，明确实际可用子集与尚不可交付的原因。

**Blocked by:** 19 — 连续提交到跨目录共享有界并发队列。

**Status:** ready-for-agent
Labels: ready-for-agent

- [ ] 已有应用管理记录的镜像可追加；重新核验与官方 SHA-256 一致的文件视为已满足，不匹配或无法安全核验停止对应操作并保留原文件。
- [ ] 非管理非空镜像不自动接管，未登记文件不自动收录或删除，未知同路径内容不被静默覆盖；重试与追加也不能绕过保护。
- [ ] 用户可主动重新核验并协调镜像索引；每次更新前检查支撑声明的全部必需文件及 hash，不只核验新增内容或信任历史状态。
- [ ] 外部删除/修改导致受影响目标声明撤下；该发行版本仍有其他齐备目标则保留，否则撤下索引行，其他有效内容继续存在。磁盘损坏文件不自动修复、删除或替换。
- [ ] 索引按实际校验通过文件生成官方事实字段和类别、语义版本降序；未登记或未核验的旧类别不能继续虚报，原始清单字节不裁剪。
- [ ] 同根索引协调串行，下载保持并发；协调中新增内容被正确纳入后续一致结果，旧协调结果不能覆盖新事实或丢失声明。
- [ ] 内容与校验文件先于完整索引替换，索引不得半写入发布；索引生成/写入失败保留正式文件和旧索引，标为未确认、尚不可交付。
- [ ] 主动协调成功后，无任何未完成写入且内容/索引一致才可交付有效子集；不要求其他下载项全部成功，附件告警不等同于索引不一致。
- [ ] 按镜像根列明可用发行版本/目标、失败/取消/告警和协调状态；LTS/EOL 不自动撤下仍有效内容，不把版本发现当作全平台安装承诺。
- [ ] 目录失联时停止受影响操作，用户重新指定对应已管理镜像后重新核验，不猜测路径或静默创建替代镜像；未来交付遵守停止该根写入及内容先于索引，不实现上传/快照。
- [ ] 应用 Interface 与实际临时目录测试覆盖首次/追加、有效文件复用、未知冲突、外部删除/修改、索引失败保留、手动恢复、多目标部分成功及协调中追加。
- [ ] 故障注入验证协调/替换中断后不会显示可交付，正式文件和旧索引受到保护；正式界面演示失败后主动恢复，不依赖尚未实现的 Nexus 上传。
